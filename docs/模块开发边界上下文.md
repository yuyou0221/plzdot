这份文档用于所有新对话开始开发某个模块前阅读。核心原则是：

```text
一个模块只处理自己的事情。
不要在开发 A 模块时，顺手开发 B 模块的页面、逻辑、业务规则或数据解释。
跨模块协作只能通过明确的输入、输出、接口和共享领域规则完成。
```

## 最高原则

每个模块必须有清晰边界：

- 本模块负责什么。
- 本模块读取哪些上游输入。
- 本模块写入哪些事实或结果。
- 本模块向下游输出什么。
- 哪些事情明确不属于本模块。

如果一个需求看起来会影响其他模块，应先写成“对其他模块的需求/接口变更建议”，不要直接在本模块里实现其他模块逻辑。

## 禁止事项

开发某个模块时，默认禁止：

- 顺手改其他模块页面。
- 顺手改其他模块业务逻辑。
- 复制其他模块的判断规则。
- 在本模块中重新计算其他模块的核心结果。
- 为了让本模块展示正确，私自改写其他模块的数据口径。
- 绕过统一接口，直接读取其他模块的底层临时字段。
- 在没有说明影响面的情况下修改共享数据库结构。
- 在没有回归检查的情况下修改排期内核、权限、导入、人员主数据等共享基础能力。

特别注意：

```text
不要因为某个页面需要一个结果，就在这个页面里重新写一套计算逻辑。
应该找到这个结果的所属模块，让所属模块输出它。
```

## 允许事项

开发某个模块时，可以做：

- 完成本模块页面。
- 完成本模块数据读取。
- 完成本模块写入接口。
- 完成本模块 Excel 导入/导出。
- 定义本模块需要的上游输入。
- 定义本模块提供给下游的输出。
- 使用已有共享领域规则。
- 使用其他模块已经公开的稳定接口。
- 给其他模块提出“需要新增什么输出”的上下文。

如果确实必须改共享层，应满足：

- 先说明为什么这是共享层问题，不是本模块问题。
- 改动范围尽可能小。
- 明确哪些模块会受影响。
- 更新对应文档。
- 跑必要验证。

## 模块边界表

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| 项目排期 | 项目规划、排期内核结果、规划视图、预测视图、上线日历、项目级风险 | 不负责产品组每日工作流、建模师分配、人员维护、财务测算细节 |
| 产品组工作指引 | 产品组任务执行、进度填写、任务完成、阻塞、备注、款式清单录入 | 不负责重新计算项目排期、不负责建模师产能、不负责财务预测 |
| 建模排期 | 款式级建模任务、建模师分配、外包状态、建模反馈、建模产能 | 不负责项目年度规划、不负责产品组其他任务、不负责重新计算项目上线预测 |
| 用户数据 | 读取唯一标准 Excel，记录、整理人员、团队、岗位、账号、权限、外包供应商等用户数据文档；提供登录功能 | 不负责项目排期逻辑、不负责建模排期算法、不负责产品组工作指引分配逻辑、不主动向其他模块输出或联动写入 |
| 数据导入 | Excel 预览、校验、合并写入、导入记录、错误提示 | 不负责解释业务预测结果，不应静默触发跨模块复杂逻辑，除非接口明确要求 |
| 财务测算 | 成本、回款、现金流、项目财务预测 | 不负责重新推导研发周期和上线预测，应读取排期内核结果 |
| 知识库 | 工作方法、流程指引、资料沉淀、AI 问答 | 不负责修改项目事实，不负责替代业务系统写入 |
| 送审 AI | 版权方/IP 送审要求检查、材料风险提示 | 不负责直接改变项目进度，除非用户明确确认写入检查结果 |

## 跨模块输入输出规则

### 项目排期对外输出

项目排期应输出：

- 项目计划上线时间。
- 项目预测上线时间。
- 项目风险等级。
- 项目当前阶段。
- 任务级计划/预测/实际完成时间。
- 里程碑状态。
- 延期完成判断。

其他模块只能读取这些结果，不应自己重算。

### 产品组工作指引对外输出

产品组工作指引应输出：

- 任务执行事实。
- 任务完成日期。
- 预计完成日期。
- 阻塞原因。
- 进度备注。
- 款式清单。
- 原画/建模前置资料。

这些事实会影响项目排期和建模排期，但必须通过明确写入接口进入系统。

### 建模排期对外输出

建模排期应输出：

- 款式建模状态。
- 建模师/外包分配。
- 预计建模工作日。
- 建模开始日期。
- 内部通过日期。
- 版权方过审日期。
- 反馈与修改记录。
- 产品组需要处理的主动事实事件。
- 项目排期可主动读取的建模完成事实。

当前固定口径：

- 建模排期只主动输出给产品组工作指引的事实事件。
- 建模排期不主动输出给项目排期。
- 建模排期不写 `ProjectTask`，不生成“确认回写项目排期”按钮。
- 项目排期需要建模完成事实时，主动读取建模排期公开接口，并由项目排期自行决定是否写执行事实、是否重新测算。

### 用户数据边界

用户数据模块的唯一输入是标准用户数据 Excel：

- 人员名单。
- 团队结构。
- 权限角色。
- 外包供应商。
- 登录账号和密码配置。

用户数据模块负责记录、整理和维护这些用户数据文档。

用户数据模块不主动对任何其他模块输出业务结果，也不触发其他模块联动写入。其他模块如果需要人员、团队、账号或权限信息，只能按需读取用户数据主数据，不应在自己的模块里维护或解释人员主数据。

权限角色只在用户数据模块中作为账号主数据记录。某个模块是否允许特定权限角色访问，由该模块自行判断，不由用户数据模块统一维护模块访问矩阵。

用户数据模块在系统里的唯一功能是提供登录功能。除登录、Excel 导入/导出和用户数据整理外，不在用户数据模块里实现项目排期、产品组工作指引、建模排期、财务、知识库或送审 AI 的业务逻辑。

## 共享层规则

共享层包括：

```text
src/lib/schedule-domain/
src/lib/schedule-engine/
src/lib/auth/
src/lib/db/
src/lib/imports/
prisma/schema.prisma
```

修改共享层时要格外谨慎，因为它可能影响多个模块。

排期相关共享规则必须放在：

```text
src/lib/schedule-domain/
src/lib/schedule-engine/
```

不要在项目排期页面、产品组工作指引页面、建模排期页面分别写一套任务编号、里程碑、状态翻译、风险判断。

计划上线月份、建议上线日期、年度规划周期、里程碑映射、状态翻译、风险判断等规则属于排期共享规则：

- 纯业务规则放在 `src/lib/schedule-domain/`。
- 需要读取/写入排期数据或触发批量重算的服务放在 `src/lib/schedule-engine/`。
- 页面组件、导入组件和 API 路由只能调用共享规则或服务，不要自己复制分配日期、风险等级、里程碑归类等逻辑。

## 数据所有权规则

每类数据只能有一个主负责模块：

| 数据 | 主负责模块 |
| --- | --- |
| 项目规划主数据 | 项目排期 |
| 排期预测结果 | 项目排期/排期内核 |
| 产品任务执行事实 | 产品组工作指引 |
| 款式建模事实 | 建模排期 |
| 人员和团队 | 用户数据 |
| 登录账号和权限 | 用户数据/权限系统 |
| Excel 导入批次 | 数据导入 |
| 财务预测 | 财务测算 |
| 送审规则 | 送审 AI/知识库 |

如果一个模块需要修改不属于自己的数据，应通过该数据所属模块提供的接口或约定流程完成。

## 开发一个模块前必须先回答

每个新对话开始做模块前，先回答这 6 个问题：

1. 这个模块本轮只做什么？
2. 这个模块不做什么？
3. 这个模块读取哪些输入？
4. 这个模块写入哪些数据？
5. 这个模块输出给谁？
6. 是否需要改共享层？如果需要，影响哪些模块？

没有回答清楚前，不要直接开始大改。

## 如果发现其他模块缺东西

不要直接补到当前模块里。

正确做法：

1. 记录当前模块需要什么。
2. 判断这个数据属于哪个模块。
3. 写一段“给对应模块的开发上下文”。
4. 等对应模块补好稳定输出。
5. 当前模块再通过接口读取。

示例：

```text
建模排期需要知道某项目任务 7-10 的预测完成时间。
这属于项目排期内核结果。
建模排期不应该自己判断任务 7-10 的预测时间。
应由项目排期/排期内核输出，然后建模排期读取。
```
