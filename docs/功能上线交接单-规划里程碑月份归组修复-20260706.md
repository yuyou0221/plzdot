## 故障现象

- 规划里程碑看板会把部分已完成里程碑按实际完成月归档。
- 规划里程碑看板会把部分未完成 / 预测延期里程碑按预测完成月归档。
- 规划里程碑看板会把部分正推计划较早的里程碑按 `plannedFinishDate` 月份归档。
- 这些都会让“规划视图”失去计划对照意义。

## 根因

`src/lib/schedule-repository.ts` 生成里程碑卡片时，规划月份原先使用：

```ts
row.plannedFinishDate ?? row.expectedFinishDate ?? row.forecastFinishDate
```

这不符合规划看板口径：

- `plannedFinishDate` 是从 `projectStartDate` 正推的管理计划，不是从计划上线倒推的里程碑目标日。
- `expectedFinishDate` / `forecastFinishDate` 是当前执行或预测信息，只能影响状态，不能移动规划月份。
- 已完成任务虽然会在预测视图中显示完成月，但规划视图不能按实际完成月重新归档。

## 修复内容

- 新增统一函数：
  - `getPlanningMilestoneDueDate`
  - `getPlanningMilestoneStatus`
- 规划里程碑月份现在只使用：
  - 对应里程碑任务的 `latestFinishDate`
  - 缺少任务级 `latestFinishDate` 时 fallback 到项目 `plannedLaunchDate`
- 大货里程碑：
  - 优先使用 #30 `latestFinishDate`
- 平面里程碑：
  - 若存在 #31，优先使用 #31 `latestFinishDate`
- 状态颜色独立计算：
  - 已完成且完成日不晚于 dueDate：`done`
  - 已完成但完成日晚于 dueDate：`doneLate`
  - 未完成且 today 晚于 dueDate：`delay`
  - 未完成且 `calculatedFinishDate` 晚于 dueDate：`delay`
  - 否则：`normal`
- 预测视图仍可显示实际完成月 / 当前预测月，不影响规划视图归组。
- 模拟脚本新增仅测试用读取参数，可以指定当前模拟批次读取里程碑卡片；正式页面仍默认只读正式测算并过滤模拟项目。

## 新增回归

新增场景：

```text
test-fixtures/schedule-scenarios/planning-milestone-month-v5.json
```

覆盖：

- 已完成晚于规划月份：规划月份仍为 `26年8月`，预测月份可显示 `26年10月`，状态 `doneLate`。
- 未完成预测延期：规划月份仍为 `26年8月`，状态 `delay`。
- `plannedFinishDate` 正推早于目标：规划月份仍为 `26年8月`。
- 平面里程碑：使用 #31 `latestFinishDate`，不被正推月份带到 8 月。
