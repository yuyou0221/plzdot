最后更新：2026-05-29

本文档是项目排期模块的开发边界、输入输出和跨模块事件契约。后续开发项目排期模块时，应先阅读：

## 模块定位

项目排期是平台的核心排期出口，负责承接项目规划、任务事实和排期内核结果，并向管理层、产品组工作指引、建模排期等模块提供稳定的排期口径。

项目排期负责：

- 项目规划主数据。
- 计划上线日期、上线月份、年度规划和上线顺序。
- 项目组、产品研发、产品研发美术、项目级建模负责人。
- 上线日历和计划调整。
- 任务事实接收和记录。
- 调用或标记统一排期内核重新测算。
- 展示排期内核输出的预测、风险、延期和里程碑结果。

项目排期不负责：

- 产品组日常任务页面功能。
- 款式级建模师分配。
- 建模产能算法。
- 人员、团队和账号主数据维护。
- 财务测算。
- 自己在组件里复制排期内核判断逻辑。

## 模块契约总览

| 类别 | 内容 |
| --- | --- |
| 输入 | 项目主数据输入、任务事实输入、计划调整输入 |
| 读取 | 用户/团队主数据、建模事实、排期内核结果、导入批次 |
| 写入 | Project、ProjectTask、ProgressUpdate、ScheduleAdjustment、TaskDragLog、导入批次、任务事实事件日志 |
| 输出 | 规划视图、压力预测视图、上线日历、表格视图、项目录入视图、任务明细、风险提醒 |
| 对外可读数据 | 项目主数据、计划上线信息、任务事实、项目预测结果、任务预测结果、风险提醒、项目级负责人字段 |

## 输入一：项目主数据输入

项目主数据输入用于创建或更新项目规划基础信息。

### 输入载体

- 项目主数据 Excel。
- 项目排期页内的表格视图。
- 项目排期页内的项目录入视图。

### Excel 工作表

建议工作表名称：

```text
项目主数据
```

已确认的人工填写字段顺序：

```text
项目编号
项目名称
版权方
IP
产品类型
年度规划
预计上线月份
项目组
产品研发
产品研发美术
建模负责人
预计款式数
项目等级
备注
```

必填字段：

```text
项目名称
版权方
IP
```

项目编号只是业务编号，可变，不作为唯一身份。

项目唯一身份是系统生成的 `projectId`。导入时匹配优先级为：

```text
1. 有 projectId 时按 projectId 匹配。
2. 没有 projectId 时按 项目名称 + 版权方 + IP 辅助匹配。
3. 仍无法匹配时，作为新项目进入预览。
```

### 字段归属

| Excel 字段 | 建议写入字段 | 说明 |
| --- | --- | --- |
| 项目编号 | `Project.projectCode` | 业务编号，可调整 |
| 项目名称 | `Project.projectName` | 必填 |
| 版权方 | `Project.licensorName` | 必填 |
| IP | `Project.ipName` | 必填 |
| 产品类型 | `Project.productType` | 人工规划字段 |
| 年度规划 | 规划字段或备注扩展 | 用于年度规划口径 |
| 预计上线月份 | `Project.plannedLaunchDate` | 月份导入时按规则生成计划上线日期 |
| 项目组 | `Project.projectTeamId` | 现阶段可存名称，后续可对齐用户数据团队 ID |
| 产品研发 | `Project.projectOwnerId` | 现阶段可存名称，后续可对齐用户 ID |
| 产品研发美术 | `Project.artOwnerId` | 现阶段可存名称，后续可对齐用户 ID |
| 建模负责人 | `Project.modelingOwnerId` | 项目级建模协调负责人，不等于具体建模师 |
| 预计款式数 | `Project.styleCount` | 立项阶段预估 |
| 项目等级 | `Project.projectLevel` | 管理层业务优先级 |
| 备注 | `Project.notes` | 只记录主数据说明 |

### 禁止导入字段

项目主数据 Excel 不允许导入计算字段：

```text
预测完成时间
预测上线时间
风险等级
延期判断
延期天数
产能超载
里程碑状态
紧急程度
```

这些字段必须由统一排期内核或规则服务计算。

## 输入二：任务事实输入

任务事实输入用于记录项目任务的真实推进情况。它有两个载体，但本质是同一种输入。

| 载体 | 用途 |
| --- | --- |
| 任务进度 Excel | 历史迁移、批量补录、阶段性导入 |
| 产品组工作指引标准事件 | 日常实时录入 |

### 任务进度 Excel

典型工作表名称：

```text
实际进度录入表
```

当前识别字段：

```text
recordKey
项目名称
taskName
taskStatus
实际开始日期
实际完成日期
项目组
推进中任务预期完成时间
父记录
```

字段映射：

| Excel 字段 | 建议写入字段 | 说明 |
| --- | --- | --- |
| recordKey | 导入行标识 / 辅助幂等键 | 可为空，不作为项目唯一身份 |
| 项目名称 | 匹配 Project | 不建议单独作为唯一匹配 |
| taskName | 匹配 ProjectTask / TaskRule | 和 taskNo 规则一起校验 |
| taskStatus | `ProjectTask.status` | 允许值见任务状态口径 |
| 实际开始日期 | `ProjectTask.actualStartDate` | 日期事实 |
| 实际完成日期 | `ProjectTask.actualFinishDate` | 日期事实 |
| 项目组 | 校验字段 | 不反向覆盖项目主数据 |
| 推进中任务预期完成时间 | `ProjectTask.expectedFinishDate` | 推进中任务事实 |
| 父记录 | 辅助追溯 | 不参与排期核心判断 |

任务进度 Excel 应先生成导入预览，校验通过后再写入，并生成导入批次。

### 任务状态口径

项目排期记录任务事实时，允许的业务状态至少包括：

```text
未开始
进行中
送审中
已完成
阻塞
暂停
```

阻塞和暂停必须分开：

```text
阻塞：外部条件卡住，必须有 blockReason。
暂停：主动暂停，不自动等同于阻塞。
```

## 产品组工作指引事件契约

产品组工作指引确认接受 `ProjectTaskFactEvent` 口径。

产品组只输出任务事实事件，不输出风险、延期、预测完成时间、预测上线日期、里程碑状态和产能结论。

### 接收入口

建议由项目排期提供：

```text
POST /api/schedule/task-fact-events
```

### TypeScript 类型

```ts
export type ProjectTaskFactEvent = {
  eventId: string;
  eventType:
    | "task_started"
    | "task_expected_finish_updated"
    | "task_submitted_for_review"
    | "task_completed"
    | "task_blocked"
    | "task_unblocked"
    | "task_paused"
    | "task_resumed"
    | "task_note_updated";
  sourceModule: "product-guide";
  projectId: string;
  taskNo: number;
  taskKey: string;
  taskName: string;
  occurredAt: string;
  operatorId: string;
  operatorName: string;
  payload: Record<string, unknown>;
};
```

字段要求：

- `eventId` 必须全局唯一，用于幂等。
- `projectId` 必须是系统生成的项目 ID。
- `taskNo` 必填，用于定位任务规则和项目任务。
- 日期字段统一使用 `YYYY-MM-DD`。
- `occurredAt` 使用带时区 ISO 字符串，例如 `2026-05-29T10:30:00+08:00`。
- `sourceModule` 固定为 `product-guide`。

### 事件类型和 payload

| 页面动作 | eventType | 关键 payload |
| --- | --- | --- |
| 更新进度为进行中 | `task_started` | `actualStartDate`, `status`, `note` |
| 更新预计完成时间 | `task_expected_finish_updated` | `expectedFinishDate`, `status`, `note` |
| 送审 | `task_submitted_for_review` | `submittedAt`, `expectedFinishDate`, `status`, `note` |
| 标记完成 | `task_completed` | `actualFinishDate`, `actualStartDate?`, `status`, `note` |
| 标记阻塞 | `task_blocked` | `status`, `blockReason`, `expectedFinishDate?`, `note` |
| 解除阻塞 | `task_unblocked` | `status`, `expectedFinishDate?`, `note` |
| 暂停 | `task_paused` | `status`, `note` |
| 恢复 | `task_resumed` | `status`, `actualStartDate?`, `note` |
| 仅备注更新 | `task_note_updated` | `status?`, `note` |

建议阻塞事件使用：

```json
{
  "status": "阻塞"
}
```

暂停事件使用：

```json
{
  "status": "暂停"
}
```

### 事件处理规则

项目排期收到事件后：

```text
1. 校验事件结构。
2. 根据 eventId 做幂等，重复事件不重复写入。
3. 根据 projectId + taskNo 定位 ProjectTask。
4. 如果 ProjectTask 不存在，按 taskNo 从任务规则初始化；如果任务规则也不存在，则拒绝。
5. 根据 eventType 写入任务事实字段。
6. 写入 ProgressUpdate，保留原始 payload。
7. 记录事件日志。
8. 标记需要重新测算，或触发统一排期内核重新测算。
```

建议新增事件日志表：

```text
ProjectTaskFactEventLog
- eventId unique
- eventType
- sourceModule
- projectId
- projectTaskId
- taskNo
- taskKey
- taskName
- occurredAt
- operatorId
- operatorName
- payload Json
- processingStatus
- errorMessage
- createdAt
```

### 事件到任务事实的映射

```text
task_started
- status = 进行中
- actualStartDate = payload.actualStartDate

task_expected_finish_updated
- expectedFinishDate = payload.expectedFinishDate
- status = payload.status ?? 进行中

task_submitted_for_review
- status = 送审中
- expectedFinishDate = payload.expectedFinishDate
- submittedAt / reviewTarget / attachmentUrls 进入事件日志和 ProgressUpdate

task_completed
- status = 已完成
- actualFinishDate = payload.actualFinishDate
- actualStartDate 有值则写入

task_blocked
- status = 阻塞
- isBlocked = true
- blockReason = payload.blockReason
- expectedFinishDate 有值则写入

task_unblocked
- isBlocked = false
- blockReason 清空
- status = payload.status ?? 进行中
- expectedFinishDate 有值则写入

task_paused
- status = 暂停
- 不自动设置 isBlocked

task_resumed
- status = 进行中
- actualStartDate 有值且原来为空则写入

task_note_updated
- 只写 progressNote / status，不影响完成日期
```

### 与建模排期事件分离

任务 7 和任务 10 可能同时触发建模排期动作，但项目排期只消费 `ProjectTaskFactEvent`。

```text
ProjectTaskFactEvent -> 给项目排期
style-submissions / style-start-events / review-results -> 给建模排期
```

项目排期不消费、不推导具体款式建模启动，不维护款式级建模师分配。

## 读取数据

项目排期可以读取以下数据，但不得在本模块中复制其业务维护逻辑：

| 数据 | 来源模块 | 用途 |
| --- | --- | --- |
| 人员、团队、账号 | 用户数据 | 展示负责人、团队、权限判断 |
| 款式建模事实 | 建模排期 | 展示建模进度摘要、作为排期内核输入 |
| 建模产能异常 | 建模排期 / 排期内核 | 风险解释和提醒 |
| 任务规则 | 排期共享规则 | 初始化任务、校验 taskNo |
| ScheduleProjectResult | 排期内核 | 项目预测结果 |
| ScheduleTaskResult | 排期内核 | 任务预测结果和任务明细 |
| Alert | 排期内核 / 提醒服务 | 风险提醒 |

## 写入数据

项目排期允许写入：

```text
Project
ProjectTask
ProgressUpdate
DataImport
ScheduleAdjustment
TaskDragLog
ProjectTaskFactEventLog
```

项目排期不直接人工写入：

```text
ScheduleProjectResult.riskLevel
ScheduleProjectResult.forecastLaunchDate
ScheduleProjectResult.delayDays
ScheduleTaskResult.riskLevel
ScheduleTaskResult.forecastFinishDate
里程碑状态
产能是否超载
```

这些结果只能来自统一排期内核。

## 输出和对外可读数据

项目排期页面输出：

- 规划视图。
- 压力预测视图。
- 上线日历。
- 表格视图。
- 项目录入视图。
- 任务明细。
- 风险提醒。

项目排期对外可读数据：

- 项目主数据。
- 计划上线日期 / 月份。
- 年度规划和上线顺序。
- 项目组、产品研发、产品研发美术、建模负责人。
- 项目任务事实。
- 项目预测结果。
- 任务预测结果。
- 风险提醒。
- 项目当前阶段摘要。
- 给产品组工作指引的任务清单。
- 给建模排期的项目节奏和建模阶段输入。

其他模块读取项目排期数据时，应通过稳定 API、repository 或 view model，不应复制项目排期页面组件里的判断逻辑。

## 开发禁止项

项目排期模块开发时禁止：

- 在组件里复制 `milestoneByTaskNo`、`forecastFinishDate`、`riskLevel`、延期判断等排期内核逻辑。
- 人工填写预测完成时间。
- 人工填写风险等级。
- 人工填写延期判断。
- 从任务进度 Excel 反向覆盖项目组等项目主数据。
- 把阻塞和暂停混为一个状态。
- 在项目排期里维护具体建模师分配。
- 在项目排期里维护用户和团队主数据。
- 在项目排期里消费建模排期的款式启动事件。
