# 平台数据结构设计草案

最后更新：2026-05-27

本文档记录当前已经确认的数据结构口径。它不是最终数据库迁移稿，而是后续设计 Prisma schema、Excel 导入接口、模块输入输出和排期内核接口时的业务基线。

## 核心判断

平台本质上不是一张巨大单表，而是一份巨大的工作簿。

应按以下类型拆分数据：

- 主数据：项目、人员、团队、版权方、IP、产品类型、供应商。
- 规划输入：年度规划、计划上线月份、项目状态、项目等级、紧急程度。
- 执行事实：任务完成、预计完成、进度更新、阻塞、款式清单、建模状态、送审反馈。
- 计算输出：排期预测、风险等级、超载判断、产能是否足够、系统建议上线日期。
- 配置规则：任务编号、任务模板、里程碑分组、产品类型规则、春节年度周期。
- 历史记录：Excel 导入批次、规划调整记录、任务变化记录、建模换人记录、反馈轮次。

强规则：

- 规划、事实、计算结果必须分开。
- 计算结果只能由排期内核或对应计算逻辑生成，不允许人工手填。
- 发现预测结果错误时，必须修改输入事实或配置，再重新测算。
- Excel 前期可以作为批量更新入口，但不能成为第二套计算逻辑。

## 项目身份

项目需要系统生成的永久 ID，作为真正唯一身份。

业务项目编号不是唯一身份。常见编号如 `26015`，表示 2026 年第 15 个上线项目，但它可能为空、后补或修改。

已确认规则：

- 项目名称很少改，但允许修改。
- 项目名称不能作为唯一键。
- 项目拆分后算新项目。
- 项目取消后复活也算新项目。
- 项目延期到下一年仍算同一个项目。
- 如果管理层修改业务编号，例如 `26022` 改为 `27004`，项目年度归属可能随之变化。
- 大多数延期到下一年的项目不一定会改业务编号。

建议字段：

| 字段 | 说明 |
| --- | --- |
| `id` | 系统生成永久 ID |
| `businessProjectCode` | 业务项目编号，例如 `26015`，允许为空和修改 |
| `name` | 项目名称 |
| `status` | 项目状态 |
| `createdAt` | 系统创建时间 |
| `updatedAt` | 系统更新时间 |

## Excel 与网页数据关系

前期 Excel 是重要的批量更新入口。

默认导入方式应为按项目合并或补充信息。全量替换是高危操作，只允许总经理执行。

已确认规则：

- P0 阶段暂时没有字段禁止 Excel 覆盖。
- 导入 Excel 前应有数据库备份。
- 后续应增加导入预览，显示新增、覆盖、缺失、异常。
- 如果 Excel 少了一个项目，默认不能直接理解为删除。
- 全量替换必须是明确动作，不能和普通导入混用。

建议导入模式：

| 模式 | 使用场景 | 权限 |
| --- | --- | --- |
| 合并补充 | 日常更新项目字段、任务事实、人员数据 | 管理者 |
| 全量替换 | 数据结构大调整、重新初始化某类数据 | 总经理 / admin |

## 项目主数据

项目刚进入系统时，最少必填字段只有：

- 项目名称
- 版权方
- IP

除以上字段和系统公式计算字段外，其他字段都允许后补。

建议字段：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| `name` | 是 | 项目名称 |
| `licensorId` | 是 | 主版权方 |
| `ipAssets` | 是 | 一个或多个 IP |
| `businessProjectCode` | 否 | 业务编号 |
| `productTypeId` | 否 | 产品类型 / 工艺类型 |
| `projectLevel` | 否 | 项目优质程度 |
| `urgencyLevel` | 否 | 项目紧急程度 |
| `priorityScore` | 否 | 综合优先级，建议由等级和紧急程度计算或辅助排序 |
| `plannedLaunchMonth` | 否 | 计划上线月份 |
| `projectTeamId` | 否 | 项目小组 |
| `productOwnerId` | 否 | 产品研发 |
| `productArtistId` | 否 | 产品研发美术 |
| `expectedStyleCount` | 否 | 立项时预估款式数 |

项目状态：

- 项目池中
- 规划中
- 已立项
- 推进中
- 暂停
- 取消
- 已完结

## 版权方、IP 与送审规则

版权方拥有 IP 的商业权益。一个版权方可以拥有多个 IP，例如新创华可以拥有奥特曼、犬夜叉、EVA 等 IP。

一个项目可能绑定多个 IP，需要支持双 IP 甚至更多 IP 联动。

建议数据结构：

| 表 | 说明 |
| --- | --- |
| `Licensor` | 版权方 |
| `IpAsset` | IP |
| `ProjectIp` | 项目与 IP 的多对多关系 |
| `ReviewRequirement` | 送审要求 |

送审要求建议支持三级：

- 版权方级规则
- IP 级规则
- 项目级补充规则

当前判断：同一版权方的要求通常近似甚至相同，但不排除某个 IP 有独立要求。

## 产品类型

已确认的产品类型包括：

- 毛绒
- 搪胶毛绒
- 搪胶
- PVC 盲盒
- PVC 挂件
- PVC mini 盲盒
- Q版手办
- 正比例手办

产品类型同时也是难度和工艺标签，因为它会直接影响任务周期、建模难度、样品难度、成本和产能测算。

建议字段：

| 字段 | 说明 |
| --- | --- |
| `name` | 产品类型名称 |
| `defaultTaskTemplateId` | 默认任务模板 |
| `defaultDifficulty` | 默认难度 |
| `notes` | 工艺说明 |

项目名称中的信息：

- `系列代数` 应结构化。
- `目标年份` 应结构化。
- `留位项目` 不单独做字段，使用项目状态 `项目池中` 表达。

## 年度规划与上线日历

年度规划单位不是自然年，而是春节后第一个月到下一个春节前，共 12 个月。

该规则同时用于年度规划和上线日历。

计划上线时间精确到月份，不人工填写具体日期。系统根据当月项目数量自动分配建议上线日期。

上线数量规则：

- 硬下限：每月不少于 2 个项目。
- 硬上限：每月不超过 5 个项目。
- 软目标：每月 3-4 个项目。

建议上线日期分配规则草案：

| 当月项目数 | 建议上线日期 |
| --- | --- |
| 1 | 1日 |
| 2 | 1日、15日 |
| 3 | 1日、10日、20日 |
| 4 | 1日、8日、15日、22日 |
| 5 | 1日、7日、13日、19日、25日 |

建议字段：

| 字段 | 说明 |
| --- | --- |
| `planningCycleId` | 春节年度周期 |
| `plannedLaunchMonth` | 计划上线月份 |
| `suggestedLaunchDate` | 系统计算建议上线日期 |
| `businessProjectCode` | 业务编号，可从中读取上线排序，但不能强依赖 |

## 任务编号、任务模板与里程碑

任务编号不能写死，必须通过配置表维护。

当前已知里程碑分组口径：

- 原画：任务编号 1-6
- 建模：任务编号 7-10
- 红蜡：任务编号 11-15、17、18
- 产前：任务编号 21-27
- 大货：任务编号 30
- 平面：平面设计相关任务，不是兜底分类

以上口径未来可能变化，所以必须进入配置表。

不同产品类型会有不同任务模板。

一个任务的计划时间绝不人工填写。任务计划时间由脚本统一计算，脚本根据以下输入倒推：

- 计划上线月份
- 产品类型
- 任务模板
- 任务规则

建议数据结构：

| 表 | 说明 |
| --- | --- |
| `TaskDefinition` | 任务定义：编号、名称、里程碑、是否关键任务 |
| `TaskTemplate` | 任务模板：适用于某类产品 |
| `TaskTemplateItem` | 模板内任务和相对周期规则 |
| `ProjectTaskPlan` | 某次测算生成的项目任务计划结果 |
| `ProjectTaskFact` | 实际执行事实 |
| `TaskChangeLog` | 每次变化历史 |

关键边界：

- `ProjectTaskPlan` 是计算输出，可以重新生成。
- `ProjectTaskFact` 是执行事实，不能被计算覆盖。
- `TaskChangeLog` 是历史记录，不能被普通导入覆盖。

## 产品组工作指引写入事实

产品组工作指引是执行事实入口，不是规划修改入口。

任务实际完成时间当前可以通过 Excel 批量写入，长期主入口应是产品研发在产品组工作指引中填写。

产品研发点击任务完成时，不只是点击按钮。不同任务需要不同完成字段。

已确认规则：

- 完成日期默认当天，但允许手动修改。
- 原画类任务完成时需要上传或关联 PNG / JPG 原画图。
- 任务未完成时，需要填写预计完成日期、当前进度、阻塞原因、备注。
- 当前进度和阻塞原因应做成下拉列表。
- 下拉列表无法覆盖的内容写入备注。
- 产品组不能随意标记任务跳过或不适用。
- 是否需要某任务必须由任务模板决定。

产品组任务状态：

- 未开始
- 进行中
- 已完成
- 阻塞
- 暂停
- 取消
- 送审中
- 工厂推进中

3 天未更新提醒规则：

- 没有关键节点时，录入任务进度算更新。
- 有关键节点时，送审、交付供应商、通过、被驳回等关键节点算更新。

建议增加配置：

| 配置 | 说明 |
| --- | --- |
| `TaskCompletionRequirement` | 每个任务完成时必须填什么字段 |
| `TaskProgressEventType` | 送审、驳回、通过、交付供应商等关键事件类型 |

## 款式清单

项目立项时通常只有大概款式数量需求。

款式数量在原画开始、原画完成、建模中、样品中都可能变化。原画完成后变化概率很小。红蜡完结并进入模具后，款式数量不允许再变化。

款式清单由产品研发美术录入。

款式需要系统永久 ID，同时需要项目内顺序号，例如第 1 款、第 2 款。顺序号允许配置或调整。

款式继承项目的产品类型和难度，但未来可支持款式级例外。

款式最少字段：

| 字段 | 说明 |
| --- | --- |
| `id` | 系统永久 ID |
| `projectId` | 所属项目 |
| `styleSequence` | 项目内顺序号 |
| `name` | 款式名称 |
| `artworkFile` | 原画图 |
| `estimatedModelingWorkdays` | 预计建模工作日 |
| `artworkApprovedAt` | 原画过审日期 |
| `modelingStartedAt` | 建模开始日 |
| `modelingInternalApprovedAt` | 建模内部通过日期 |
| `modelingApprovedAt` | 建模版权方过审日期 |

原画与建模关系：

- 所有款式原则上必须原画过审后才能开始建模。
- 特殊情况允许提前建模，但需要审批备注，审批可以后置。

建议字段：

| 字段 | 说明 |
| --- | --- |
| `earlyModelingApprovalNote` | 原画未过审提前建模的审批备注 |
| `isRequired` | 是否必做款式，后续需要时启用 |

## 建模排期

建模状态：

- 未分配
- 已排期
- 建模中
- 修改中
- 已送审
- 等反馈
- 已通过
- 外包中
- 暂停
- 取消

暂不增加 `内部检修中`。内部检修包含很多零碎时间，先不作为主状态。

已确认规则：

- 建模师和外包供应商可以同时存在。
- 内部建模师可以负责检修，外包负责制作。
- 一个款式可以换建模师。
- 换建模师必须保留历史分配记录，并记录换人时的当前进度。
- 预计建模工作日由建模组长填写。
- 跑半年后，系统应根据真实历史数据给出建议工作日。
- 内部通过日期和版权方过审日期必须分开。
- 版权方驳回后，需要产生一轮反馈记录，状态退回 `修改中`。
- 驳回修改会增加内部建模实际消耗时长。

建议数据结构：

| 表 | 说明 |
| --- | --- |
| `ModelingTask` | 当前款式建模任务主记录 |
| `ModelingAssignmentHistory` | 分配和换人历史 |
| `ModelingFeedbackRound` | 送审、反馈、驳回、修改、通过轮次 |

## 建模产能

建模师产能按每周可用工作日记录。

休假、请假、临时不可排期必须进入产能计算。

外包不记录可用产能，只记录实际用时。

超载规则：

```text
个人手头待消化建模工时 > 24 个工作日 = 超载
```

建模产能的核心判断：

```text
按照当前排期，所有正在建模和即将建模的项目，是否能确保该项目的建模阶段在最短 4 周、最长 8 周内被产能消化。
```

建模排期主看板输出：

- 建模产能是否 OK
- 每个建模师任务
- 未分配款式
- 外包款式
- 超载人员
- 卡在修改 / 送审的款式

每款消耗时长建议单独做统计页，不放在主看板。

## 用户、团队、岗位与权限

组织结构需要区分公司部门和项目小组。

公司部门包括：

- 产品团队
- 原画团队
- 建模团队
- 平面设计团队
- 样品团队
- 新媒体运营团队
- 商务团队
- 供应链团队

项目小组属于产品团队下面，例如：

- 忍者组
- 迪no组
- 丹东组
- 易特凡组

项目小组一般是 1 个产品研发 + 1 个产品研发美术，但不是硬性固定。

一个人可以承担多个业务角色。

权限角色和业务岗位必须分开。

建议结构：

| 表 | 说明 |
| --- | --- |
| `User` | 人员和账号基础信息 |
| `Department` | 公司部门 |
| `ProjectTeam` | 项目小组 |
| `UserBusinessRole` | 一个人的多个业务角色 |
| `AuthRole` | 系统权限角色 |

权限角色示例：

- admin
- manager
- viewer

业务岗位示例：

- 总经理
- 产品总监
- 产品研发
- 产品研发美术
- 建模师
- 原画师
- 样品
- 平面设计

建模师能力标签暂时废弃，不进入近期结构设计。

## 模块输入输出边界

### 项目规划 / 项目排期

输入：

- 项目主数据
- 计划上线月份
- 产品类型
- 任务模板和任务规则
- 产品组工作指引写入的执行事实
- 建模排期写入的款式状态和建模结果
- 用户数据中的产能和人员归属

输出：

- 规划视图
- 压力预测
- 里程碑看板
- 上线日历
- 风险提示
- 计算出的预测完成日期

不允许：

- 人工修改预测完成日期
- 人工修改风险等级
- 模块自行复制一套排期算法

### 产品组工作指引

输入：

- 项目排期当前任务
- 项目组归属
- 建模排期反馈信号
- 版权方反馈

写入：

- 任务完成日期
- 预计完成日期
- 当前进度
- 阻塞原因
- 备注
- 关键节点事件
- 款式清单

输出：

- 本周需完成
- 本周在推进
- 本周要开始
- 风险任务
- 版权方反馈
- 待建模款式事实

### 建模排期

输入：

- 项目排期中的建模窗口
- 产品组工作指引录入的款式清单
- 用户数据中的建模师和每周可用工作日
- 请假 / 不可排期记录
- 外包实际用时记录

写入：

- 款式分配
- 换人历史
- 建模状态
- 预计建模工作日
- 建模开始日
- 内部通过日期
- 送审反馈轮次
- 版权方过审日期
- 外包供应商

输出：

- 建模产能是否 OK
- 每个建模师任务
- 未分配款式
- 外包款式
- 超载人员
- 卡在修改 / 送审的款式

### 用户数据

输入 / 写入：

- 人员
- 账号
- 权限
- 公司部门
- 项目小组
- 业务岗位
- 建模师每周可用工作日
- 请假 / 不可排期记录

输出：

- 产品组工作指引默认项目小组
- 建模排期可排建模师
- 权限控制
- 组织结构
