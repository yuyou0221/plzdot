## 业务口径

#8 打印灰模实物确认、#9 工程审核是展示型旁路任务，不参与主链排期测算，只计算应开始 / 应结束。

#8/#9 不应影响：

- `projectedLaunchDate`
- #30 / #31 的 calculated 日期
- `isBlockingLaunch`
- `blockingLaunchTasks`
- 项目延期判断
- 主关键路径

#8/#9 仍保留 planned / latest / calculated / actual 等日期展示，用于提醒。

## 根因

原有任务模板中 #8/#9 已有 `sideTask` 标记，但排期结果生成阶段没有把它们统一当作 `nonSchedulingTask`：

- 风险等级仍可能按普通任务计算为严重 / 高风险。
- 项目级 summary 的部分风险统计仍可能包含旁路任务。
- 建模里程碑主完成判断仍可能把 #8/#9 当作必需完成项。
- #8/#9 的 calculated 日期仍按自身 56 天工期独立推进，没有稳定跟随 #10。

## 修复内容

- 在排期内核中定义 `DISPLAY_ONLY_SIDE_TASK_IDS = [8, 9]`。
- #8/#9 结果行写入：
  - `sideTask = true`
  - `nonSchedulingTask = true`
  - `displayOnlySideTask = true`
- #8/#9 永远不作为 `isLaunchPath` / `isBlockingLaunch`。
- #8/#9 的 calculated 日期跟随 #10：
  - 自己有 `actualFinishDate` 时，使用自己的实际完成日。
  - #10 有 `actualFinishDate` 时，按 #10 推断完成。
  - 否则使用 #10 的 `calculatedFinishDate`。
  - `calculatedStartDate = calculatedFinishDate - 自身 durationDays`，且不早于项目启动日。
- #8/#9 落后时输出提醒级别，不再制造“影响上线 / 严重阻塞上线”结论。
- 项目级 `behindPlanTasks`、`blockingLaunchTasks`、`noBufferTasks` 统计排除 `nonSchedulingTask`。
- 建模里程碑主完成 / 风险判断排除 #8/#9。
- 新增回归场景：`side-tasks-8-9-v5`。
