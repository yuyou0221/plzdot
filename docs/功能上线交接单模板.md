# 功能上线交接单模板

用途：当某个模块或功能开发完毕，准备合并到 `staging` 或部署服务器时，把这份交接单填写完整后发给开发中控。

开发中控会根据这份交接单判断：

- 是否可以合并到 `staging`。
- 是否需要补验证。
- 是否需要数据库迁移。
- 是否可以部署服务器。
- 是否存在跨模块风险。

## 基本信息

```text
模块名称：
开发分支：
本轮目标：
是否已经提交：
是否已经 push 到远端：
交接总结文档路径：
```

## 改动范围

```text
改动文件清单：

新增/修改 API：

新增/修改数据库结构：

是否包含 Prisma migration：

是否影响登录/权限：

是否影响排期内核：

是否影响其他模块：
```

## 验证情况

```text
npm run lint：

npm run build：

页面验证：

真实数据/样本验证：

浏览器控制台是否有报错：

接口是否验证：
```

## 上线要求

```text
需要上线的环境：

是否需要执行数据库迁移：

是否需要执行 prisma generate：

是否需要重启服务：

是否需要导入 Excel 或初始化数据：

是否需要备份数据库：
```

## 风险与遗留

```text
已知风险：

未完成事项：

需要中控确认的问题：

回滚方式：
```

## 最简版

如果时间紧，至少提供下面这些信息：

```text
开发分支：
改了什么：
影响哪些模块：
是否有数据库迁移：
lint 是否通过：
build 是否通过：
页面是否验证过：
是否需要部署服务器：
已知风险：
```

## 给模块对话的提示词

可以把下面这段发给完成开发的模块对话：

```text
请按照 docs/功能上线交接单模板.md，整理一份给开发中控的上线合并交接单。

请明确写出：
1. 当前开发分支。
2. 改动文件。
3. 新增或修改的 API。
4. 是否有数据库迁移。
5. 是否影响其他模块。
6. npm run lint 和 npm run build 是否通过。
7. 页面和真实数据是否验证。
8. 是否需要服务器部署、迁移或重启。

只整理交接单，不要直接合并到 staging。
```
