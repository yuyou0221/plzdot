# P0 数据导入总方案

最后更新：2026-05-27

本文档定义 P0 阶段所有 Excel / CSV / JSON 数据如何进入系统。它衔接《P0 数据字典》《现有 Prisma Schema 对照改造清单》和《P0 数据库迁移分阶段方案》。

目标不是让 Excel 永远成为主系统，而是在内部测试前期允许通过 Excel 暴力更新数据，同时保证：

- 导入有分类。
- 匹配有规则。
- 覆盖有边界。
- 导入前能预览。
- 导入后能追踪。
- 需要重新测算时必须明确提示。

## 导入总原则

1. Excel 只能写输入数据，不能写系统计算结果。
2. 预测完成日期、风险等级、超载判断、建议上线日期只能由系统计算。
3. 普通导入默认是合并或补充，不是删除。
4. 全量替换是高危操作，只允许总经理 / admin 执行。
5. 导入前必须生成预览，至少显示新增、更新、疑似冲突、无法匹配。
6. 导入前必须能备份数据库，尤其是 staging。
7. 导入后必须生成 `DataImport` 批次记录。
8. 导入影响排期输入时，必须提示需要重新测算或自动触发统一排期内核。
9. 同一类数据只能有一个合法导入入口，不能各模块各写一套解析逻辑。
10. 导入脚本必须保留原始文件名、导入人、导入时间和摘要。

## 导入类型总览

| 导入类型 | 主要来源 | 目标数据 | 默认模式 | 是否触发重算 |
| --- | --- | --- | --- | --- |
| 项目主数据导入 | 项目规划 Excel | 项目、版权方、IP、产品类型、上线月份、项目组 | 合并补充 | 是 |
| 任务进度导入 | 实际进度 Excel | 项目任务事实、进度事件 | 合并补充 | 是 |
| 款式清单导入 | 产品组 / 款式 Excel | 款式、原画图、原画过审、预计建模工作日 | 合并补充 | 是 |
| 建模排期导入 | 建模排期 Excel | 建模任务、建模状态、分配、外包、反馈 | 合并补充 | 是 |
| 用户组织导入 | HC 表 / 用户数据 Excel | 人员、部门、项目小组、岗位、权限、产能 | 合并补充 | 视情况 |
| 排期结果导入 | 排期内核 JSON | ScheduleRun、ScheduleProjectResult、ScheduleTaskResult | 追加最新批次 | 否 |

## 通用导入流程

```text
上传 / 指定文件
→ 识别导入类型
→ 解析文件
→ 字段标准化
→ 匹配已有记录
→ 校验数据质量
→ 生成导入预览
→ 用户确认
→ 备份数据库
→ 写入数据库
→ 生成 DataImport
→ 必要时触发重新测算
→ 输出导入报告
```

## 通用匹配优先级

### 项目匹配

优先级：

1. 系统项目 ID
2. 业务项目编号
3. 项目名称 + 主 IP + 版权方
4. 项目名称 + IP
5. 项目名称

规则：

- 仅项目名称匹配到多条时，必须进入人工确认。
- 项目名称变化时，业务项目编号和系统 ID 优先。
- 项目拆分、取消后复活应新建项目，不能覆盖旧项目。
- 延期到下一年仍是同一项目。

### 人员匹配

优先级：

1. 用户 ID
2. 登录名
3. 姓名 + 部门
4. 姓名

规则：

- 仅姓名匹配到多条时，必须人工确认。
- 不允许导入时直接删除人员。
- 登录名、密码、权限角色不应被普通 HC 导入随意覆盖。
- 密码哈希不允许通过 Excel 导入。

### 款式匹配

优先级：

1. 款式 ID
2. 项目 ID + 款式顺序号
3. 项目 ID + 款式名称
4. 项目名称 + 款式顺序号
5. 项目名称 + 款式名称

规则：

- 同项目内款式顺序号重复必须报错或人工确认。
- 款式名称重复但顺序号不同，可以保留。
- 红蜡完结并进入模具后，款式数量不允许普通导入修改。
- 虚拟款式不能作为真实款式导入。

### 建模任务匹配

优先级：

1. 建模任务 ID
2. 款式 ID
3. 项目 ID + 款式顺序号
4. 项目 ID + 款式名称
5. 项目名称 + 款式名称

规则：

- 换建模师必须生成分配历史。
- 外包和内部建模师可以同时存在。
- 状态变更应记录更新时间和更新人。

### 项目任务匹配

优先级：

1. 项目任务 ID
2. 项目 ID + 任务编号
3. 业务项目编号 + 任务编号
4. 项目名称 + 任务编号
5. 项目名称 + 任务名称

规则：

- 任务编号优先于任务名称。
- 任务名称匹配不到任务编号时，必须用任务规则表辅助匹配。
- 无法匹配任务编号的行必须进入异常报告。

## 导入模式

### 合并补充

默认模式。

行为：

- 已有记录：按字段覆盖或补充。
- 新记录：创建。
- 文件中缺失的旧记录：不删除。
- 可生成“疑似停用 / 疑似遗漏”提示。

适用：

- 日常项目更新。
- 任务实际进度更新。
- 建模排期更新。
- 用户组织更新。

### 只补空值

行为：

- 仅当系统字段为空时写入。
- 已有值不覆盖。

适用：

- 从旧 Excel 补版权方、IP、产品类型。
- 从 HC 表补人员联系方式。
- 从历史建模表补缺失款式信息。

### 全量替换

高危模式。

行为：

- 指定数据范围内，以文件为准。
- 文件中缺失的旧记录可能被停用、删除或归档，具体需按导入类型定义。

权限：

- 仅总经理 / admin。

要求：

- 必须备份数据库。
- 必须预览。
- 必须显示将被停用 / 删除 / 覆盖的记录数。
- 必须二次确认。

## 导入类型 1：项目主数据导入

### 来源

常见文件：

- 项目规划 Excel
- 项目信息表
- 年度项目规划表

当前参考：

```text
番茄项目规划信息收集 (10).xlsx
```

### 目标表

当前短期目标：

- `Project`
- `TaskRule`
- `ProjectTask`
- `ScheduleRun`
- `ScheduleProjectResult`
- `ScheduleTaskResult`

阶段 1 后新增目标：

- `Licensor`
- `IpAsset`
- `ProjectIp`
- `ProductType`
- `PlanningCycle`

### 核心字段

| 字段 | 是否必需 | 说明 |
| --- | --- | --- |
| 项目名称 | 是 | 项目最小必填 |
| 版权方 | 是 | 项目最小必填 |
| IP | 是 | 项目最小必填，可多 IP |
| 业务项目编号 | 否 | 如 `26015` |
| 产品类型 | 否 | 影响任务模板 |
| 计划上线月份 | 否 | 精确到月份 |
| 项目状态 | 否 | 项目池中、规划中等 |
| 项目等级 | 否 | 优质程度 |
| 紧急程度 | 否 | 时间压力 |
| 项目组 | 否 | 忍者组、迪no组等 |
| 产品研发 | 否 | 后补 |
| 产品研发美术 | 否 | 后补 |
| 建模负责人 | 否 | 项目级建模负责人，后补 |
| 预估款式数 | 否 | 后续可能被款式清单修正 |

### 校验

必须校验：

- 项目名称是否为空。
- 版权方是否为空。
- IP 是否为空。
- 同一文件内是否出现疑似重复项目。
- 同名项目是否匹配到多个旧项目。
- 计划上线月份格式是否正确。
- 每月上线数量是否超过硬限制。

建议校验：

- 项目编号年份和计划上线月份是否明显冲突。
- 产品类型是否在系统产品类型列表里。
- 项目组和人员是否能匹配用户数据。

### 写入规则

- 普通导入默认合并补充。
- 项目不存在时创建。
- 项目存在时更新可覆盖字段。
- 文件少了项目，不代表删除。
- 全量替换时才允许停用文件中缺失的项目。

### 导入后动作

- 触发统一排期内核重新测算。
- 生成新的 `ScheduleRun`。
- 更新项目排期看板。
- 提示用户查看导入报告。

## 导入类型 2：任务进度导入

### 来源

常见文件：

- 实际进度录入表
- 周度任务跟进表
- 历史任务完成 Excel

### 目标表

当前：

- `ProjectTask`
- `ProgressUpdate`

阶段 3 后：

- `ProjectTask`
- `TaskProgressEvent` 或补字段后的 `ProgressUpdate`

### 核心字段

| 字段 | 是否必需 | 说明 |
| --- | --- | --- |
| 项目 | 是 | 用于匹配项目 |
| 任务编号 | 是 | 优先匹配任务 |
| 任务名称 | 否 | 任务编号缺失时辅助匹配 |
| 实际开始日期 | 否 | 事实 |
| 实际完成日期 | 否 | 事实 |
| 预计完成日期 | 否 | 事实 |
| 任务状态 | 否 | 未开始、进行中等 |
| 当前进度 | 否 | 下拉值 |
| 阻塞原因 | 否 | 下拉值或备注 |
| 备注 | 否 | 补充 |

### 校验

必须校验：

- 项目是否能匹配。
- 任务编号是否能匹配任务规则。
- 日期格式是否合法。
- 下游任务已开始但上游任务未完成的异常。
- 任务实际完成日期早于实际开始日期的异常。

建议校验：

- 进行中超过 3 天无更新。
- 预计完成日期晚于计划完成日期。
- 任务 10 已开始但任务 7 未完成。

### 写入规则

- 写入任务事实，不写入计划时间。
- 每次实际值变化都应生成历史记录。
- Excel 可以覆盖当前事实字段，但不能删除历史。
- 计划开始 / 计划完成仍由排期内核生成。

### 导入后动作

- 提示需要重新测算。
- 可自动触发排期内核。
- 更新产品组工作指引。
- 更新项目排期预测视图。

## 导入类型 3：款式清单导入

### 来源

常见文件：

- 产品组款式清单
- 原画完成清单
- 过渡建模款式导出

### 目标表

阶段 2 前：

- `ModelingTask`
- `ProjectModelingProgress`

阶段 2 后：

- `Style`
- `ModelingTask`
- `ProjectModelingProgress`

### 核心字段

| 字段 | 是否必需 | 说明 |
| --- | --- | --- |
| 项目 | 是 | 款式所属项目 |
| 款式名称 | 是 | 款式最小字段 |
| 款式顺序号 | 建议必填 | 项目内第几款 |
| 原画图 | 是 | PNG / JPG 或链接 |
| 原画过审日期 | 是 | 原则上过审后建模 |
| 预计建模工作日 | 是 | 建模组长填写 |
| 建模开始日 | 否 | 可由建模排期写 |
| 建模内部通过日期 | 否 | 产品研发美术写 |
| 建模过审日期 | 否 | 版权方通过 |
| 提前建模审批备注 | 条件必填 | 原画未过审但已开始建模时必填 |

### 校验

必须校验：

- 项目是否能匹配。
- 款式名称是否为空。
- 同项目款式顺序号是否重复。
- 原画未过审但建模开始是否有审批备注。
- 红蜡完结 / 进入模具后是否还在新增款式。

建议校验：

- 预计建模工作日是否明显异常。
- 原画图格式是否是 PNG / JPG 或合法链接。
- 款式数和项目预估款式数差异过大。

### 写入规则

- 产品研发美术是长期主维护人。
- Excel 是过渡批量入口。
- 普通导入不删除款式。
- 要取消款式，应写状态为取消，而不是静默删除。

### 导入后动作

- 影响建模排期。
- 影响项目建模进度。
- 影响项目排期预测输入。
- 提示需要重新测算。

## 导入类型 4：建模排期导入

### 来源

常见文件：

- 建模排期系统 Excel
- 建模款式导出 Excel
- 外包进度表

当前已知文件：

```text
皮特易凡建模排期系统.xlsx
建模排期系统-忍者组.xlsx
建模排期系统-迪no&厦大.xlsx
建模排期系统-丹东组.xlsx
建模款式导出-20260525-服务器上传.xlsx
```

### 目标表

当前：

- `ModelingTask`
- `ModelingFeedback`
- `ProjectModelingProgress`

阶段 2 后：

- `Style`
- `ModelingTask`
- `ModelingAssignmentHistory`
- `ModelingFeedback`
- `ProjectModelingProgress`

### 核心字段

| 字段 | 是否必需 | 说明 |
| --- | --- | --- |
| 项目 | 是 | 匹配项目 |
| 款式 | 是 | 匹配款式 |
| 建模状态 | 是 | 未分配、建模中等 |
| 当前建模师 | 否 | 可为空 |
| 外包供应商 | 否 | 可与建模师同时存在 |
| 预计工作日 | 是 | 建模组长填写 |
| 剩余工作日 | 否 | 产能计算 |
| 计划开始日 | 否 | 建模排期 |
| 计划完成日 | 否 | 建模排期 |
| 实际开始日 | 否 | 建模事实 |
| 内部通过日期 | 否 | 产品研发美术验收 |
| 送审日期 | 否 | 提交版权方 |
| 版权方过审日期 | 否 | 最终通过 |
| 反馈轮次 | 否 | 可由反馈记录计算 |
| 反馈内容 | 否 | 版权方意见 |

### 校验

必须校验：

- 项目是否能匹配。
- 款式是否能匹配或创建。
- 建模状态是否在枚举内。
- 预计工作日是否为正数。
- 建模开始日是否早于原画过审日；若是，必须有审批备注。
- 换建模师时是否记录当前进度。

建议校验：

- 已通过但没有版权方过审日期。
- 等反馈但没有送审日期。
- 修改中但没有反馈内容。
- 一个人手头待消化建模工时是否超过 24 工作日。
- 所有正在建模和即将建模项目是否能在 4-8 周内消化。

### 写入规则

- 普通导入可以更新建模状态。
- 换建模师必须生成历史。
- 外包不记录固定产能，只记录实际用时。
- 虚拟款式不能导入为真实款式。

### 导入后动作

- 更新建模排期。
- 更新项目建模进度。
- 如果建模 7-10 相关事实变化，提示需要重新测算。
- 不静默修改项目规划基线。

## 导入类型 5：用户组织导入

### 来源

常见文件：

- HC 表
- 用户数据 Excel
- 人员名单 CSV

当前已知文件：

```text
公司各部门hc表 (2).xlsx
user-data-personnel-form-20260525.xlsx
```

### 目标表

当前：

- `Team`
- `User`
- `OutsourceVendor`

阶段 4 后：

- `Team`
- `User`
- `UserBusinessRole`
- `ModelerCapacity`
- `OutsourceVendor`

### 核心字段

| 字段 | 是否必需 | 说明 |
| --- | --- | --- |
| 姓名 | 是 | 人员名称 |
| 登录名 | 否 | 有账号才填 |
| 权限角色 | 否 | admin / manager / viewer |
| 公司部门 | 否 | 产品团队、建模团队等 |
| 项目小组 | 否 | 忍者组等 |
| 业务岗位 | 否 | 产品研发、建模师等 |
| 是否建模师 | 否 | 建模排期读取 |
| 默认每周可用工作日 | 否 | 建模产能 |
| 状态 | 否 | 启用、停用 |
| 联系方式 | 否 | 补充 |

### 校验

必须校验：

- 姓名是否为空。
- 登录名是否重复。
- 权限角色是否在枚举内。
- 同名人员是否可能重复。
- 项目小组是否属于产品团队。

建议校验：

- 建模师没有每周可用工作日。
- 产品小组没有产品研发或产品研发美术。
- 离职 / 停用人员仍被项目或建模任务引用。

### 写入规则

- 普通导入不删除人员。
- 文件中缺失的人员只提示疑似停用。
- 密码不能通过普通 Excel 明文覆盖。
- 登录名、权限角色应谨慎覆盖。
- 手动修正过的姓名、项目组、权限要在预览里提示。

### 导入后动作

- 更新用户数据页。
- 更新产品组工作指引默认项目组。
- 更新建模排期可排建模师。
- 通常不需要触发排期重算，除非建模产能变化已经接入预测。

## 导入类型 6：排期结果导入

### 来源

排期内核输出 JSON。

当前常见文件：

```text
project-task-estimates-v5.json
```

### 目标表

- `ScheduleRun`
- `ScheduleProjectResult`
- `ScheduleTaskResult`
- 必要时同步 `Project`
- 必要时同步 `ProjectTask`

### 规则

- 这是计算结果导入，不是人工 Excel 输入。
- 只能由统一排期内核输出。
- 导入时生成新的测算批次。
- 页面读取最新成功批次。
- 不允许人工编辑这些结果字段。

### 导入后动作

- 更新项目排期。
- 更新产品组工作指引的派生任务。
- 更新建模里程碑读取结果。
- 不需要再次触发重算。

## DataImport 批次记录

所有导入都要记录：

| 字段 | 说明 |
| --- | --- |
| `importType` | 导入类型 |
| `mode` | 合并补充、只补空值、全量替换 |
| `sourceFileName` | 原文件名 |
| `sourceFilePath` | 保存路径 |
| `rowCount` | 行数 |
| `importStatus` | 成功、失败、部分成功 |
| `errorMessage` | 错误信息 |
| `importedBy` | 导入人 |
| `importedAt` | 导入时间 |
| `backupPath` | 导入前备份 |
| `rawMetadata` | sheet、预览摘要、异常数量 |

当前 `DataImport` 需要补：

- `mode`
- `backupPath`
- `previewMetadata`

## 导入预览

每次导入确认前至少展示：

| 指标 | 说明 |
| --- | --- |
| 新增记录数 | 将创建多少条 |
| 更新记录数 | 将覆盖多少条 |
| 只补空值数 | 仅补充多少字段 |
| 无法匹配数 | 需要人工处理 |
| 疑似重复数 | 可能重复 |
| 疑似停用数 | 文件中缺失但系统中存在 |
| 高风险覆盖数 | 涉及权限、状态、上线月份等 |
| 触发重算 | 是 / 否 |

## 导入异常分级

### 阻断错误

不能继续导入：

- 文件格式无法解析。
- 必填字段缺失。
- 项目匹配到多条且无法判断。
- 款式顺序号严重重复。
- 日期格式大面积错误。
- 用户登录名重复。

### 警告

可以导入，但必须展示：

- 项目编号年份和计划上线月份不一致。
- 项目组无法匹配。
- 建模开始早于原画过审，但有审批备注。
- 建模师产能缺失。
- 一个人超载。
- 每月上线数量低于或超过软目标。

### 信息

仅记录：

- 新增版权方。
- 新增 IP。
- 新增产品类型。
- 新增项目小组。
- 新增外包供应商。

## 前端导入入口建议

短期不建议每个模块各做复杂导入。

建议做一个统一入口：

```text
/imports
```

功能：

- 选择导入类型。
- 上传 Excel。
- 显示预览。
- 确认导入。
- 显示导入报告。
- 必要时触发重新测算。

各模块页面可以保留快捷入口，但最终调用同一套导入服务。

## P0 优先级

建议先做：

1. 项目主数据导入规范化。
2. 用户组织导入规范化。
3. 建模排期导入规范化。
4. 款式清单导入规范化。
5. 任务进度导入规范化。

理由：

- 项目主数据是全站基础。
- 用户组织决定权限、项目小组、建模产能。
- 建模排期已经有真实数据和使用压力。
- 款式清单是产品组工作指引和建模排期的长期边界。
- 任务进度导入最终要被产品组工作指引逐步替代。

## 与迁移阶段的关系

| 迁移阶段 | 导入影响 |
| --- | --- |
| 阶段 0 | 建备份和统计，不改导入 |
| 阶段 1 | 项目主数据导入写结构化版权方、IP、产品类型 |
| 阶段 4 | 用户组织导入写项目小组、业务角色、建模可用工作日 |
| 阶段 2 | 款式和建模导入写 `Style`、`ModelingTask`、换人历史 |
| 阶段 3 | 任务进度导入写事件历史和完成要求 |
