## 项目目标

搭建一个公司内部项目管理平台，辅助管理层和各团队做项目规划、动态排期、产能分配、任务跟进、财务测算、知识库与送审检查。

首版不是面向全公司正式上线，而是先给少数人试用，用真实数据跑通关键流程，再逐步扩展。

## 已确认核心模块

后续建议按模块拆新对话实现：

1. 项目规划
   每年根据市场状况、项目优质程度做下一年度项目规划。项目规划改动会影响动态排期与财务测算。

2. 项目排期与动态预测
   根据项目排期和实际进度生成规划视图、预测视图、风险提示和项目详情。

3. 上线日历
   每年日历从春节后的第一个月到下一个春节，共 12 个月。按当月应上线项目显示，可通过拖拽调整规划。

4. 建模排期
   每个原画设计稿对应一款建模。建模按款式分配，可多人并行，也可外包。

5. 月度 / 周度任务
   根据动态排期给各组员设定月度和周度任务。月度任务可以视为四周周度任务组合。

6. 产能排期
   包含原画、建模、样品、平面设计、生产五类产能。

7. 财务测算
   项目研发周期、成本、回款进度会影响排期。项目规划或动态排期变动后，需要看到未来财务测算。

8. 知识库
   帮助同事高效做事，后续适合接入 AI。

9. 版权方送审要求检查
   每个版权方有自己的送审要求和标准，需要 AI 辅助检查是否出错。

10. 原画比稿 / 问卷调研
    当前人工记录问卷调研，后续做成网页功能减少工作量。

11. 人员名单与权限
    第一版少数人试用，暂不做登录和权限。后续正式使用时再补。

## 当前 P0 优先级

第一次内部上线包已确定为四个模块：

- 项目排期
- 产品组工作指引
- 建模排期
- 用户数据

建议实现顺序：

1. 用户数据基础版
2. 项目排期稳定版
3. 建模排期基础版
4. 产品组工作指引

当前完成状态：

```text
项目排期 + 上线日历：基础版已完成，仍需继续稳定拖拽持久化与重新测算
用户数据：基础版已完成
建模排期：基础版已完成
产品组工作指引：未开始
```

内部上线前最低标准：

- 真实数据能稳定导入
- 四个模块页面都能跑通
- 不出现明显错误口径
- 有简单访问保护，不裸露公网
- 有数据备份方式
- 高风险操作先做草稿，不直接覆盖真实排期

首版可以先不做：

- 其余模块都可以暂缓
- 登录与权限暂缓

不能出错的业务规则：

- 财务
- 排期
- 送审

管理层最关心：

- 大家工作量是否能完成
- 是否超标
- 是否有任务阻塞
- 是否有延期风险
- 是否存在异常，例如任务耗时过久或长时间没进度

## 页面与设计偏好

用户偏好：

- 希望网页美观、易读、易操作
- 喜欢插画风
- 希望后续提供两套风格：扁平风格与插画风格，可切换

产品形态判断：

- 这是内部运营工具，不应做营销式落地页
- 首页应直接是可用的工作台
- 应保持信息密度、可扫描性、明确的状态颜色和高效操作

## 当前开发原则

新对话接手时应遵守：

- 先读本文件和对应模块上下文，不要重新猜业务规则
- 不要一次横跨多个模块做大改
- 每个模块独立验收
- 修改排期、财务、送审相关逻辑时必须明确口径
- 所有关键页面修改后要跑 `npm run lint` 和 `npm run build`
- 前端视觉改动后要在浏览器里验证
- 真实业务样本优先用小鸟4代、自嘲熊、猫福珊迪2等已讨论过的项目做回归检查

## 建议的新对话拆分方式

每个新对话只做一个模块。例如：

```text
请阅读 docs/项目管理平台-当前总控上下文.md
请阅读 docs/模块任务上下文-项目排期与上线日历.md
本轮只处理项目排期与上线日历模块，不处理建模排期和财务测算。
```

模块完成后，应输出一份交接记录，至少包含：

- 做了什么
- 改了哪些文件
- 改了哪些业务口径
- 验证了哪些真实项目
- 还有哪些问题没做
