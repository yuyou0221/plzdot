## 项目目标

搭建一个公司内部项目管理平台，辅助管理层和各团队做项目规划、动态排期、产能分配、任务跟进、财务测算、知识库与送审检查。

## 已确认核心模块

后续建议按模块拆新对话实现：

1. 项目规划
   每年根据市场状况、项目优质程度做下一年度项目规划。项目规划改动会影响动态排期与财务测算。

2. 项目排期与动态预测
   根据项目排期和实际进度生成规划视图、预测视图、风险提示和项目详情。

3. 上线日历
   每年日历从春节后的第一个月到下一个春节，共 12 个月。按当月应上线项目显示，可通过拖拽调整规划。

4. 建模排期
   每个原画设计稿对应一款建模。建模按款式分配，可多人并行，也可外包。

5. 月度 / 周度任务
   根据动态排期给各组员设定月度和周度任务。月度任务可以视为四周周度任务组合。

6. 产能排期
   包含原画、建模、样品、平面设计、生产五类产能。

7. 财务测算
   项目研发周期、成本、回款进度会影响排期。项目规划或动态排期变动后，需要看到未来财务测算。

8. 知识库
   帮助同事高效做事，后续适合接入 AI。

9. 版权方送审要求检查
   每个版权方有自己的送审要求和标准，需要 AI 辅助检查是否出错。

10. 原画比稿 / 问卷调研
    当前人工记录问卷调研，后续做成网页功能减少工作量。

11. 人员名单与权限
    用户数据基础版已完成，登录与权限基础版已完成。当前已有 admin / manager / viewer 三类角色。

## 系统输入输出关系

当前系统按四层理解：

```text
基础数据层
↓
计划 / 测算层
↓
执行工作台层
↓
反馈回写层
```

核心模块关系：

```text
用户数据 → 项目排期 / 建模排期 / 产品组工作指引
项目规划 → 项目排期规划视图
项目排期 → 产品组工作指引
项目排期 → 建模排期
产品组工作指引 → 项目任务进度回写
产品组工作指引 → 款式清单录入 → 建模排期
建模排期 → 款式建模状态 → 项目排期预测视图
项目排期预测结果 → 财务测算 / 管理层提醒
```

系统级边界：

```text
规划视图 = 管理层计划基线
预测视图 / 压力预测 = 计划基线 + 执行事实 + 产能规则后的动态测算
产品组工作指引 = 执行动作入口，可写事实，但不能改规划基线
建模排期 = 款式级建模任务的数据源
用户数据 = 人员、团队、产能、擅长类型、稳定外包的数据源
登录与权限 = 访问保护、角色判断、写接口权限边界
Excel 数据接口 = 前期批量更新输入数据的临时入口
```

## 项目排期输入口径

项目排期必须拆成两套输入口径：

```text
规划输入：只允许总经理 / 产品总监维护
预测输入：接受产品组工作指引、建模排期、用户数据等执行事实
```

规划视图可接受的输入：

- 项目是否立项
- 项目名称
- IP / 版权方
- 产品类型
- 项目等级 / 优先级
- 项目路线
- 计划上线日期
- 计划款数 / 规格
- 是否需要三视图
- 项目组
- 产品研发
- 产品研发美术
- 初始项目状态
- 任务规则版本

预测视图 / 压力预测可接受的输入：

- 产品组工作指引写入的任务实际完成日期
- 产品组工作指引写入的预计完成日期
- 产品组工作指引写入的阻塞、备注和进度说明
- 产品组工作指引创建的款式清单
- 建模排期写入的款式分配、状态、送审、反馈、通过
- 用户数据中的人员产能、擅长类型、稳定外包

强规则：

```text
产品组工作指引可以写进度，但不能改规划。
建模排期可以写款式状态，但不能改规划。
用户数据可以改产能，但不能改规划。
项目排期负责重新测算，不直接替代管理层决策。
```

## 规划调整规则

管理层手动调整规划里程碑时：

```text
允许单独提前某个里程碑月份。
不允许单独把某个里程碑向后推。
```

允许：

```text
原建模里程碑：8月
调整后：7月
```

不允许：

```text
原建模里程碑：8月
调整后：9月
```

原因：

- 规划视图代表公司希望达成的计划基线
- 如果现实做不到，应体现在预测视图 / 风险提示 / 压力预测里
- 如果确实要推迟整体计划，应通过调整项目计划上线日期或管理层重新规划处理

规划调整可优先复用现有 `ScheduleAdjustment` 表。每次调整应记录：

- 调整人
- 调整时间
- 调整字段
- 原值
- 新值
- 调整原因
- 是否已重新测算

保存校验：

- 操作人必须是总经理或产品总监
- 计划上线日期不能为空
- 项目路线不能为空
- 单独调整里程碑时，目标月份不能晚于原规划月份
- 如果调整计划上线日期导致整体排期向后，必须记录原因
- 如果项目已上线 / 已完结，默认不允许改规划，除非走「修正历史数据」

## 建模排期基础版现状

当前 `/modeling` 已完成基础版，侧边栏入口为「建模排期」。

建模排期当前定位：

- 读取项目排期中的建模里程碑。
- 读取和展示款式级 `ModelingTask`。
- 支持建模师分配、外包标记、状态推进和反馈记录的基础保存。
- 给管理层、建模负责人、个人建模师提供不同视角。
- 不允许建模排期直接修改规划视图、项目计划上线日期或项目排期基线。

页面结构：

- `/modeling` 默认进入 `里程碑` 视图，不直接进入款式看板。
- 顶部视图包括：`里程碑`、`管理层看板`、`款式看板`、`个人信息`。
- `里程碑` 视图从项目排期测算数据中提取建模里程碑，按本月要完成、之前未完成、下个月要完成展示。
- 建模里程碑按项目排期任务编号 `7-10` 聚合。
- 项目已经进入红蜡、模具、大货、已完结等后续阶段时，历史建模里程碑不再作为当前逾期重点显示。
- `管理层看板` 用于查看总体建模任务、建模师负载、未分配、外包、卡住、超载和项目级建模进度。
- 当前已有基础角色权限，但管理层看板的可见性限制还没细化；后续应只允许总经理或指定管理角色查看。
- `款式看板` 按人分组，而不是按状态分列；包含未分配、各建模师、外包中等分组。
- 款式看板里的建模师身份卡不显示产能数字。
- 已通过款式不会出现在活跃排期列表里，`已通过款式` 入口放在款式看板内部。
- `个人信息` 视图当前用建模师下拉选择模拟当前用户；后续应绑定当前登录建模师。

数据读取规则：

- 如果数据库存在真实 `ModelingTask`，优先显示真实款式。
- 只有没有真实款式时，才根据 `Project.styleCount` 生成虚拟款式。

## 产品组工作指引回写规则

产品组工作指引可以写执行事实，但写入的是其他模块的数据表，不独立制造另一套真相。

允许写入：

| 动作 | 写入对象 | 是否影响预测 |
|---|---|---:|
| 标记任务已完成 | `ProjectTask.status`、`actualFinishDate`、`ProgressUpdate` | 是 |
| 修改实际完成日期 | `ProjectTask.actualFinishDate`、`ProgressUpdate` | 是 |
| 填写预计完成日期 | `ProjectTask.expectedFinishDate`、`progressNote`、`ProgressUpdate` | 是 |
| 标记任务阻塞 | `ProjectTask.isBlocked`、`blockReason`、`ProgressUpdate` | 是 |
| 解除阻塞 | `ProjectTask.isBlocked`、`ProgressUpdate` | 是 |
| 录入款式清单 | `ModelingTask` | 是，影响建模排期 |
| 标记原画过审（后续） | `ModelingTask.originalArtStatus`、`originalArtApprovedDate` | 是，释放建模任务 |
| 添加普通备注 | `progressNote` | 否，只更新说明 |

说明：上表是完整业务口径；当前基础版已落地的是标记完成、预计完成日期、阻塞 / 解除阻塞、录入款式清单。标记原画过审、正式重新测算标记、SOP / 知识库联动还没做。

完成任务的强规则：

```text
工作指引里所有“完成”按钮都必须写入实际完成日期。
默认实际完成日期 = 今天，允许手动修改。
```

保存后建议流程：

```text
写入执行事实
→ 记录 ProgressUpdate
→ 标记需要重新测算
→ 页面提示“已有进度更新，建议重新测算”
→ 管理层或负责人点击重新测算
```

第一版不建议每次保存都自动测算，避免频繁计算和误操作。

## 产品组工作指引动作生成

产品组工作指引不是简单任务列表，而是把系统信号翻译成产品组能执行的动作。

动作清单来源：

- 项目排期：当前关键任务、风险等级、预测完成日期、延期原因
- 项目任务：实际完成、预计完成、是否阻塞、最后更新时间
- 建模排期：未分配款式、送审、等反馈、修改、全部通过日期
- 用户数据：项目组、产品负责人、产品美术、人员归属
- 规划调整：管理层提前的里程碑、计划调整要求

每日动作必须包含：

- 当前关键任务未完成
- 任务有延期风险或必然延期
- 进行中超过 3 天未更新
- 缺少预计完成日期
- 管理层提前里程碑
- 款式清单未录入
- 原画已到计划完成窗口但未过审
- 建模款式未分配
- 建模卡在送审 / 等反馈 / 修改
- 项目阻塞

动作优先级：

```text
紧急：必然延期 / 阻塞 / 管理层提前要求
重要：延期风险 / 超 3 天未更新 / 建模卡住
本周处理：本周应完成 / 缺少预计完成日期 / 未录入款式
提前准备：下周准备 / 普通跟进
```

动作关闭规则：

```text
动作不是单独关闭，而是由底层事实变化自动消失。
```

例如：

- 任务已完成 → 任务动作消失
- 预计完成日期已填写 → 缺少预计时间动作消失
- 款式清单已录入 → 录入款式动作消失
- 款式已分配 → 未分配动作消失
- 阻塞解除 → 阻塞动作消失
