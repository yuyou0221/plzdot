# 项目排期模拟测试说明

最后更新：2026-07-05

## 目标

项目排期模块需要持续用稳定的模拟数据做回归测试。模拟测试用于验证：

- 项目主数据能进入排期数据结构。
- 产品组任务事实事件能被项目排期接收。
- 阻塞、暂停、完成、预计完成等任务事实不会混用。
- 任务事实接收后能自动创建重算批次并调用统一排期内核。
- 排期内核能基于模拟项目重新测算。
- 里程碑看板和上线日历能读到统一排期结果。
- 2026、2027、2028 等跨年项目不会被页面漏掉。

## 使用命令

列出当前场景：

```bash
npm run schedule:simulate -- --list
```

运行全部场景：

```bash
npm run schedule:simulate
```

只运行一个场景：

```bash
npm run schedule:simulate -- --scenario core-smoke
```

清理模拟数据：

```bash
npm run schedule:simulate -- --cleanup-only
```

运行后自动清理：

```bash
npm run schedule:simulate -- --cleanup-after
```

## 数据隔离

模拟数据全部带有批次标记：

```text
schedule-simulation:<scenarioId>:<timestamp>
```

项目名称会带前缀：

```text
[模拟:<scenarioId>]
```

脚本每次正式回放前会清理旧的模拟批次，只处理带有 `schedule-simulation:` 前缀的数据，不会主动清理真实项目。

默认运行后会留下最新一批模拟数据，方便在页面上查看效果。如果只想做自动化回归，可以使用 `--cleanup-after`。

## 场景文件位置

```text
test-fixtures/schedule-scenarios/
```

场景文件使用 JSON。一个场景通常包含：

- `projects`：模拟项目主数据。
- `taskRules`：本场景需要的任务规则。
- `events`：模拟产品组输出的 `ProjectTaskFactEvent`。
- `directEngineCases`：不经过数据库，直接喂给内核的原始输入用例，适合覆盖 Excel/脚本输入层边界。
- `expect`：需要自动校验的结果。

如果事件需要走和接口一致的“写事实 + 自动重算”闭环，在事件上设置：

```json
{
  "autoRecalculate": true
}
```

新增场景时，优先按业务情况命名，例如：

- `delayed-launch`
- `blocked-task-risk`
- `completed-project-visible`
- `excel-import-merge`
- `calendar-cross-year`

## 验收建议

项目排期模块后续每次改动，至少运行：

```bash
npm run lint
npm run build
npm run schedule:simulate
```

如果改了数据库结构，先执行：

```bash
npm run db:migrate
npm run db:generate
```
