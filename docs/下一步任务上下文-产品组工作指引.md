# 下一步任务上下文-产品组工作指引

最后更新：2026-05-25

这份文档用于新对话继续推进「产品组工作指引」。本轮建议目标不是扩大页面数量，而是把产品组工作指引做成真正可靠的执行事实入口。

## 新对话使用方式

新对话开始时建议直接发：

```text
请阅读 docs/项目管理平台-当前总控上下文.md
请阅读 docs/模块交接总结-产品组工作指引基础版.md
请阅读 docs/下一步任务上下文-产品组工作指引.md

本轮只处理产品组工作指引，不处理建模排期大改、项目排期大重构、财务、知识库完整系统、权限登录和送审 AI。
目标是补齐产品组工作指引作为“执行事实入口”的关键能力。
```

## 当前基础版状态

已完成：

- `/product-guide` 页面和侧边栏入口。
- 按项目组独立展示。
- 子页包括 `里程碑` 和 `本周工作指引`。
- 里程碑页支持 `规划视图 / 压力预测`。
- 本周工作指引分为五类：本周需完成、本周在推进、本周要开始、风险任务、版权方反馈。
- 支持标记完成、更新预计完成日期、标记阻塞、解除阻塞、录入建模款式。
- 当前不改规划基线，不改项目计划上线日期。

当前没做：

- 正式 `待重新测算` 标记。
- 标记原画过审。
- 款式清单的完整维护。
- SOP / 知识库正式接入。
- 登录态下自动识别当前项目组。

## 推荐下一步优先级

### P1：执行事实闭环

推荐先做这个，因为产品组工作指引的核心价值是让产品负责人每天能把真实进度写进去，并且让系统知道哪些项目需要重新测算。

要做的能力：

- 标记完成时允许确认实际完成日期。
- 更新预计完成日期后，任务条和详情立即刷新。
- 标记阻塞时必须填写阻塞原因。
- 解除阻塞时记录解除时间和说明。
- 每次执行动作后写入 `ProgressUpdate`。
- 页面显示「已有执行更新，建议重新测算」的提示。
- 在项目详情或任务详情里显示最近一次更新记录。

边界：

- 不要保存后自动改规划视图。
- 不要自动推迟项目计划上线日期。
- 不要每次保存后自动跑完整排期测算。
- 第一版可以只提示需要重新测算，由管理层或负责人手动触发。

验收标准：

- 标记任务完成后，再打开页面能看到任务已完成。
- 填预计完成日期后，任务详情能看到新日期。
- 标记阻塞后，任务进入风险或阻塞提示。
- 解除阻塞后，阻塞提示消失。
- 操作后能看到最近更新记录。
- 页面能提示该项目存在待重新测算的执行事实。

### P1：款式清单质量化录入

推荐和执行事实闭环一起做，或紧接着做。原因是建模排期长期依赖产品组工作指引提交款式基础资料，但 `ModelingTask` 的生成和状态维护归建模排期。

当前旧入口已经兼容桥接到建模排期款式清单提交契约。下一步要让产品负责人用系列表格提交一份靠谱的款式清单。

要做的能力：

- 在项目详情或任务详情中展示系列级款式清单。
- 支持新增、编辑款式名称和款式序号。
- 支持一次提交完整系列，例如 7-14 款。
- 必须且只能选择 1 款作为第一款建模款式。
- 支持设置是否必做。
- 支持设置款式难度：简单、标准、困难、换色、正比例等。
- 支持设置预计建模工时或预计天数。
- 支持标记原画状态：未开始、草稿、待过审、已过审、需修改。
- 支持标记原画过审日期。
- 支持填写参考图链接。
- 提交后状态为 `待确认`，等待建模侧确认。
- 建模侧确认后，产品组保存返回的 `modelingTaskId` 映射。

边界：

- 产品组工作指引负责提交款式基础资料、第一款标记、任务 7/10 启动事件、审核 / 送审结果。
- 建模排期负责分配建模师、推进建模状态、记录反馈。
- 产品组工作指引不要直接决定建模师排期。
- 产品组工作指引不要直接把项目排期任务 10 标记完成。
- 产品组工作指引不要直接维护建模状态、外包供应商、建模产能。

验收标准：

- 提交款式后，`/modeling` 能看到 `待确认` 的真实 `ModelingTask`。
- 建模确认后，产品组能拿到 `modelingTaskId`。
- 未过审款式在建模排期里要有清楚标记，不应被误认为可立即建模。
- 款式难度和预计天数能在建模排期里展示。
- 必做款式和非必做款式能区分。

### P2：工作指引解释更人话

当前页面已经不直接展示脚本状态，但下一步可以继续提升普通负责人的可读性。

要做的能力：

- 把脚本状态翻译成负责人能理解的原因。
- 例如 `等待前置实际完成 #7` 应显示为「精细建模确认风格未填完成，所以根据效果图建模暂不能确认完成」。
- 风险任务显示「为什么提醒我」「我下一步该做什么」。
- 建模相关任务显示「需要联系谁」「是否等版权方反馈」「是否需要产品美术检修」。

边界：

- 先做固定规则文案，不急着接 AI。
- 不要引入知识库完整系统。

## 建议本轮不要做

- 登录权限。
- 通知推送。
- AI 自动生成 SOP。
- 完整知识库系统。
- 财务测算。
- 项目排期规划视图编辑。
- 建模排期批量分配。

## 关键业务规则

产品组工作指引可以写执行事实，但不能改规划。

允许写入：

- 任务实际完成日期。
- 任务预计完成日期。
- 阻塞状态和阻塞原因。
- 进度备注。
- 款式清单。
- 原画过审状态。

不允许写入：

- 项目计划上线日期。
- 项目路线。
- 项目等级。
- 规划里程碑月份。
- 建模师排期。
