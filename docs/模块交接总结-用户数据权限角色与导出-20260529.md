## 本轮模块边界

用户数据模块是平台的人和组织主数据模块，但本轮边界已经收窄：

- 唯一输入：标准用户数据 Excel。
- 唯一系统功能：提供登录功能。
- 负责维护：人员名单、团队结构、岗位/业务角色、登录账号、权限字典、建模师每周可用工作日、外包供应商。
- 不负责：项目排期、建模排期、产品组工作指引、财务、知识库、送审 AI 的业务逻辑。
- 不主动向其他模块输出业务结果，不触发跨模块联动写入。
- 其他模块需要人员、团队、账号或权限时，自行读取用户数据主数据。
- 某个模块是否允许特定角色访问，由该模块自行判断；用户数据模块不维护模块访问矩阵。

## 导入规则

当前用户数据导入为覆盖更新：

- 只支持 `.xlsx`。
- 每次导入都会按 Excel 覆盖当前用户数据。
- 有 ID 时优先按 ID 匹配。
- 没有 ID 时，人员按姓名辅助匹配，团队按团队名称辅助匹配，外包供应商按供应商名称辅助匹配。
- Excel 中缺失的人员、团队、外包供应商不会物理删除，会统一停用。
- `初始/重置密码` 会写入登录密码哈希，并保存一份可导出的加密副本。
- 数据库不裸存明文密码；admin 导出时可从加密副本还原到 Excel。

导入接口：

```text
POST /api/users/import-excel
```

当前允许导入角色：

```text
admin, manager
```

## 导出规则

导出接口：

```text
GET /api/users/export-excel
```

当前仅 `admin` 可导出。

导出 Excel 工作表：

- `人员名单`
- `固定字段`
- `团队结构`
- `外包供应商`

导出的 `人员名单` 会包含 `初始/重置密码` 列。只有曾通过本系统导入或重置过明文密码的账号，才能还原导出密码；历史上只保存哈希的旧账号无法反推出明文。

## 上传 / 部署注意

后续服务器更新时常规执行：

```bash
git pull --ff-only origin staging
npm ci
npm run db:generate
npm run db:migrate
npm run build
pm2 restart project-management-staging
```

数据库迁移会新增可导出密码密文字段和权限字典表，并把早期权限矩阵字段移除。

服务器环境需要确保：

```text
AUTH_SECRET
PASSWORD_EXPORT_SECRET
DATABASE_URL
```

其中 `PASSWORD_EXPORT_SECRET` 用于可导出密码的加密/解密。staging / production 缺少该变量时不会回退，导入、导出和修改密码会返回明确错误。
