## 上线要求

```text

是否需要执行数据库迁移：需要
- 执行 prisma migrate deploy。
- 迁移会给 User 增加 permissionLevel，默认 9，并将已有 authRole='admin' 的账号设为 0。

- Next.js 服务需要重新构建并重启。

是否需要导入 Excel 或初始化数据：
- 不强制。
- 若服务器已有账号和用户数据，可先不导入。
- 若需要更新用户数据，使用用户数据页的 Excel 覆盖导入流程。

是否需要备份数据库：建议备份
- 本轮包含 User 字段迁移、用户数据覆盖导入能力、停用账号删除能力。
```

## 风险与遗留

```text
已知风险：
- 用户数据 Excel 导入是覆盖更新，生产使用前建议先备份数据库。
- 明文密码导出符合当前内部使用需求，但 staging / production 必须配置稳定的 PASSWORD_EXPORT_SECRET；正式环境不再回退使用 AUTH_SECRET。
- 非等级 0 的用户数据页访问依赖岗位 / 业务角色文本识别 HR、人事、人力资源、human resources。
- 停用账号删除会阻止有业务引用的账号，但仍建议删除前确认。

未完成事项：
- 请假 / 不可排期记录已纳入用户数据 Excel 的「不可排期记录」工作表，后续跨模块读取由对应模块按边界推进。
- 用户数据与产品组工作指引、建模排期、项目排期的正式读写联动仍由后续模块按边界推进。
- 账号权限更细粒度的字段级配置表尚未单独落库，目前是代码规则。

需要中控确认的问题：
- staging 部署时是否保留服务器现有账号密码。
- PASSWORD_EXPORT_SECRET 是否已在服务器环境固定配置。
- 是否先备份服务器数据库后再迁移。
- 是否需要先由管理员重新导入最新标准 Excel。

回滚方式：
- 代码回滚到合并前版本。
- 如已执行迁移，User.permissionLevel 新字段可保留不影响旧代码；若必须完全回滚，需数据库备份恢复。
- 如已执行 Excel 覆盖导入，需要用上线前数据库备份恢复用户数据。
```
