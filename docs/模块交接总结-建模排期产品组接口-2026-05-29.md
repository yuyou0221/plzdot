# 模块交接总结：建模排期 × 产品组接口

日期：2026-05-29

分支：

```text
feature/modeling-schedule-contract-20260529
```

## 本轮目标

落地建模排期与产品组工作指引的开发契约：

- 产品组提交完整款式清单。
- 建模排期生成 / 更新 `ModelingTask`，新建默认 `未启动`。
- 产品组提交任务 7 / 10 启动事件。
- 建模排期将款式从 `未启动` 推进到 `未分配`。
- 产品组提交内部审核 / 送审结果。
- 建模排期维护状态、日期和反馈记录。
- 产品组通过建模排期接口读取款式状态和项目建模进度。

## 新增 / 修改 API

新增：

```text
POST /api/modeling/style-submissions
POST /api/modeling/style-start-events
POST /api/modeling/review-results
GET  /api/modeling/projects/[projectId]/styles
GET  /api/modeling/projects/[projectId]/progress
```

保留：

```text
PATCH /api/modeling/tasks/[id]
```

## 新增状态

```text
未启动
待送审
```

状态流：

```text
未启动 -> 未分配 -> 已排期 / 外包中 -> 建模中 -> 待送审 -> 已送审 -> 等反馈 -> 已通过
内部不通过 / 送审不通过 -> 修改中
```

## 产品组输入

产品组只主动提交：

- 款式基础信息
- 第一款标记 `isFirstModelingStyle`
- 原画图 / 参考图 URL
- 任务 7 / 任务 10 启动事件
- 内部审核 / 送审结果

## 建模排期输出 / 对外可读

产品组可读取：

- `modelingTaskId`
- 款式编号 / 款式名 / 是否第一款
- 建模状态
- 建模师 / 外包供应商
- 内部通过日期
- 版权方过审日期
- 最新反馈
- 修改轮次
- 是否卡住
- 项目建模进度

## 边界说明

建模排期负责：

- `ModelingTask` 生成和更新
- 建模状态维护
- 外包和建模师分配
- 建模反馈记录
- 建模进度计算

产品组工作指引不维护：

- 建模师
- 外包供应商
- 建模状态
- 建模产能
- 建模进度计算
