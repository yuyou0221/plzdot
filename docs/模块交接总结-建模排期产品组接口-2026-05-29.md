## 本轮目标

落地建模排期与产品组工作指引的开发契约，并完成第一个输入功能：系列级款式清单提交与建模确认。

- 产品组按系列提交完整款式清单。
- 建模排期生成 / 更新 `ModelingTask`，新建默认 `待确认`。
- 款式清单提交后，建模排期生成专属待办 `款式清单待确认`。
- 建模侧在同一张系列款式清单页整批确认或整批退回。
- 建模侧确认款式清单后，款式才进入 `未启动`。
- 确认 / 退回接口返回完整 `styles` 清单，给产品组程序保存 `sourceStyleId` 与 `modelingTaskId` 的映射。
- 被退回的系列可以完整重新提交，不能漏款。
- 产品组提交任务 7 / 10 启动事件。
- 建模排期将款式从 `未启动` 推进到 `未分配`。
- 任务 8 / 9 启动事件会被拒绝。
- 重复启动保持幂等，并返回启动 / 跳过摘要。
- 建模师提交成果后返回 `reviewRequest`，给产品组生成待审核入口。
- 建模师提交成果时写入 `ModelingFeedback.submissionSnapshot`，记录递交前状态、恢复目标、工时、成果和提交人。
- 产品审核 / 送审结果新增前置校验：未提交成果不能审核，未进入送审阶段不能写版权方结果。
- 产品组提交内部审核 / 送审结果。
- 建模排期维护状态、日期和反馈记录。
- 产品组通过建模排期接口读取款式状态和项目建模进度。
- `FIX-...`、`LOCAL-...`、`RESUBMIT-...`、`fixture-...` 等模拟器字段统一视为测试字段，仅 `admin` 可见。

## 新增状态

```text
待确认
退回补充
未启动
待送审
```

状态流：

```text
待确认 -> 未启动 -> 未分配 -> 已排期 / 排队中 / 外包中 -> 建模中 -> 待验收 -> 待送审 -> 已送审 -> 等反馈 -> 已通过
退回补充 -> 待确认
内部不通过 / 送审不通过 -> 排队中
```

## 产品组输入

产品组只主动提交：

- 系列级款式基础信息
- 第一款标记 `isFirstModelingStyle`
- 原画图 / 参考图 URL
- 退回补充后的完整系列重新提交
- 任务 7 / 任务 10 启动事件
- 内部审核 / 送审结果

## 建模排期输出 / 对外可读

产品组可读取：

- `modelingTaskId`
- `sourceStyleId`
- `projectTaskId`
- 任务编号 `taskNo`
- 款式编号 / 款式名 / 是否第一款
- 是否必做
- 难度 / 预计建模天数
- 原画过审信息 / 参考图
- 建模状态
- 建模师 / 外包供应商
- 内部通过日期
- 版权方过审日期
- 最新反馈
- 修改轮次
- 累计建模工时
- 反馈次数
- 是否卡住
- 项目建模进度

## 边界说明

建模排期负责：

- `ModelingTask` 生成和更新
- 建模状态维护
- 外包和建模师分配
- 建模反馈记录
- 建模进度计算

产品组工作指引不维护：

- 建模师
- 外包供应商
- 建模状态
- 建模产能
- 建模进度计算

## 已验证

```text
npx prisma generate
npx prisma migrate deploy
npm run lint
npm run build
```

并用临时测试项目验证：

- 系列级款式清单提交可创建多条 `ModelingTask`，模拟器已验证 5 款系列。
- 款式清单提交后先进入 `待确认`，并生成建模专属待办 `款式清单待确认`。
- 待办打开同一张系列款式清单页，不再逐款分散确认。
- 确认前任务 7 启动、分配、计时、成果提交都会被拒绝。
- 建模侧整批确认后，当前系列全部进入 `未启动`。
- 确认返回的 `styles` 已包含 `projectId`、`projectTaskId`、`taskNo`、`modelingTaskId`、`sourceStyleId`、款式基础信息和确认后状态，可供产品组程序录入映射。
- 确认会生成 `style_list_confirmed` 事件，并写入 `ModelingProductGuideEvent`。
- 建模侧整批退回补充时必须填写原因，并写入反馈记录。
- 退回会生成 `style_list_returned` 事件，并写入 `ModelingProductGuideEvent`。
- 退回补充后可以完整重新提交同一系列，重新提交后不会漏掉原系列款式。
- 任务 7 启动第一款，任务 10 启动其余款式。
- 未确认 / 退回补充状态下，任务 7 / 10 启动会被拒绝。
- 任务 8 / 9 启动会被拒绝。
- 重复启动不会重复推进状态，返回 `startedCount=0` 和跳过原因。
- 建模师提交成果后状态进入 `待验收`，并返回给产品组的 `reviewRequest`。
- 建模师提交成果会生成 `modeling_work_submitted` 事件，并写入 `ModelingProductGuideEvent`。
- `reviewRequest` 包含 `submittedFromStatus`、`restoreStatusOnRejection`、`submittedWorkMinutes` 和 `submissionSnapshot`。
- 产品组驳回后，建模排期按快照恢复到 `排队中`，并保留建模师、外包、工时、成果和历史反馈。
- 产品组内部审核只允许写入 `待验收` 款式。
- 版权方送审结果只允许写入 `待送审` / `已送审` / `等反馈` 款式。
- 内部通过可送审后状态变为 `待送审`。
- 内部不通过 / 送审不通过必须填写文字反馈，状态回到 `排队中`。
- 审核 / 送审结果支持结构化附件：`feedbackAttachments.imageUrl`、`feedbackAttachments.pdfUrl`、`feedbackAttachments.pptUrl`，兼容 `attachmentUrls`。
- 模拟器已加入内部驳回图片 + PDF、版权驳回 PPT、驳回空文字拦截、通过类空文字的检查。
- 测试字段仅 `admin` 可见，普通页面不展示 `FIX-...` 等模拟器编号。
- 项目进度不把 `待确认` / `退回补充` 计入正式建模进度和产能。
