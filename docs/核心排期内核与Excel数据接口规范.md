# 核心排期内核与 Excel 数据接口规范

最后更新：2026-05-25

这份文档用于统一两个关键口径：

1. 项目排期脚本是平台唯一排期内核。
2. 前期允许通过几份 Excel 暴力更新基础数据，但必须走固定字段接口。

## 核心原则

```text
项目排期脚本 = 唯一排期测算真相
Excel 数据接口 = 前期批量更新数据的临时入口
各业务模块 = 写入执行事实 + 读取统一测算结果
```

任何模块都不应自己重新实现排期逻辑。

## 唯一排期内核

当前核心脚本来自：

```text
project-analysis-scripts-latest-2026-05-25.zip
```

平台内当前对应文件：

```text
legacy/schedule-engine/project-schedule-core.cjs
legacy/schedule-engine/project-analysis-v5-excel.cjs
legacy/schedule-engine/extract_project_excel.py
legacy/schedule-engine/export_chinese_excel.py
legacy/schedule-engine/generate-weekly-analysis.cjs
```

排期内核负责：

- 任务编号。
- 任务依赖。
- 标准天数。
- 路线 A / B。
- 是否需要三视图。
- 春节和节假日规则。
- 计划排期。
- 实际进度套入。
- 后置任务推断完成。
- 预测完成日期。
- 延期、风险、阻塞上线判断。
- 周度 / 月度任务分析。

## 模块使用规则

项目排期模块：

```text
可以展示规划视图、预测视图、上线日历。
可以触发统一排期内核重新测算。
不能引入第二套任务规则。
```

产品组工作指引：

```text
可以写任务实际完成、预计完成、阻塞、备注、款式清单、原画状态。
必须读取统一排期结果来展示风险和本周任务。
不能自己判断项目是否延期。
```

建模排期：

```text
可以写款式级建模分配、状态、外包、反馈、通过日期。
必须读取统一排期任务 7-10 来判断项目级建模里程碑。
不能自己重算项目上线日期。
```

用户数据：

```text
可以写人员、团队、产能、建模能力、外包供应商。
不能直接改排期结果。
```

财务测算：

```text
后续必须读取统一排期内核输出的预测上线、延期天数、项目状态。
不能自己推研发周期。
```

```text
outputs/excel-data-interface-20260525/01-项目排期核心数据接口.xlsx
outputs/excel-data-interface-20260525/02-用户与权限数据接口.xlsx

outputs/excel-data-interface-20260525/04-产品组执行事实接口.xlsx
```

这些 Excel 是前期批量更新数据的临时接口。后续可以做导入按钮或后台导入脚本。

## Excel 1：项目排期核心数据接口

文件：

```text
01-项目排期核心数据接口.xlsx
```

用途：

- 项目规划输入。
- 项目实际进度输入。
- 统一排期内核测算结果输出。

主要 sheet：

- `项目信息`
- `实际进度录入`
- `任务规则-只读`
- `最新项目测算-只读`
- `最新任务测算-只读`

导入影响：

- `项目信息` 会影响 `Project`。
- `实际进度录入` 会影响 `ProjectTask`。
- 导入后应触发统一排期内核重新测算。

不建议编辑：

- `projectId_勿改`
- `recordKey`
- `任务规则-只读`
- 测算结果只读 sheet

## Excel 2：用户与权限数据接口

文件：

```text
02-用户与权限数据接口.xlsx
```

用途：

- 维护团队。
- 维护人员。
- 维护登录名和权限角色。
- 维护建模能力标签。
- 维护外包供应商。

主要 sheet：

- `团队`
- `人员与账号`
- `建模能力标签`
- `外包供应商`

导入影响：

- `Team`
- `User`
- `ModelerCapabilityTag`
- `OutsourceVendor`

强规则：

- 不导出 `passwordHash`。
- 不允许通过 Excel 直接写密码 hash。
- 重置密码应走系统接口或专门的初始密码字段。
- 删除人员使用 `status=停用`，不物理删除。

## Excel 3：建模排期数据接口

文件：

```text
03-建模排期数据接口.xlsx
```

用途：

- 维护真实款式级建模任务。
- 维护建模师分配。
- 维护外包状态和供应商。
- 维护建模状态。
- 维护建模反馈。

主要 sheet：

- `款式建模任务`
- `建模反馈`
- `项目建模进度-只读`

导入影响：

- `ModelingTask`
- `ModelingFeedback`
- `ProjectModelingProgress`

强规则：

- 只有真实 `ModelingTask` 可以导入。
- 虚拟款式不能导入。
- 虚拟款式不能回写项目任务。
- 所有必做真实款式已通过后，才允许提示回写项目任务「根据效果图建模」。

## Excel 4：产品组执行事实接口

文件：

```text
04-产品组执行事实接口.xlsx
```

用途：

- 产品负责人批量更新任务完成。
- 产品负责人批量更新预计完成日期。
- 产品负责人批量更新阻塞和备注。
- 产品负责人维护款式清单和原画状态。

主要 sheet：

- `任务进度更新`
- `阻塞与备注`
- `款式清单与原画状态`
- `最近更新记录-只读`

导入影响：

- `ProjectTask`
- `ProgressUpdate`
- `ModelingTask`

强规则：

- 只写执行事实。
- 不修改项目规划基线。
- 不修改项目计划上线日期。
- 导入后提示需要重新测算，不静默改项目排期。

## 建议导入流程

前期可以先使用后台脚本导入，不急着做前端上传按钮。

建议流程：

```text
1. 导出当前 Excel 数据接口
2. 用户编辑 Excel
3. 后台导入脚本读取 Excel
4. 做字段校验和预览
5. 生成待更新差异
6. 用户确认
7. 写入数据库
8. 标记需要重新测算
9. 运行统一排期内核
10. 更新 ScheduleRun / ScheduleProjectResult / ScheduleTaskResult
```

不建议：

```text
上传后直接静默覆盖数据库
上传后直接改规划视图
上传后不重新测算就展示为最新预测
```

## 后续工程任务

建议拆成三步：

### 第一步：文档和导出稳定

已完成：

- 输出 4 份 Excel 数据接口。
- 写明字段边界和导入影响。

### 第二步：导入预览

需要做：

- 读取 Excel。
- 对比数据库。
- 显示新增、更新、停用、异常。
- 不直接写库。

### 第三步：确认导入和重新测算

需要做：

- 用户确认后写库。
- 生成 `DataImport`。
- 写入 `ProgressUpdate` 或调整记录。
- 标记需要重新测算。
- 运行统一排期内核。
- 展示导入结果和测算批次。

## 回归检查项目

每次改排期内核、Excel 导入或模块展示，都至少检查：

- 小鸟4代：延期完成口径。
- 兔老大表情包mini：前置任务填表错误识别。
- 无牙仔猫猫：启动晚导致整体预测晚。
- 插画小人mini2代：任务 10 已开始但任务 7 未完成的异常。

## 最重要的边界

```text
Excel 可以暴力更新输入数据。
排期结果必须由统一排期内核重新生成。
任何模块不能因为读到 Excel 或数据库字段，就自己推导一套排期结果。
```
