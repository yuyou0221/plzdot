# 下一步任务上下文-用户数据

最后更新：2026-05-25

这份文档用于新对话继续推进「用户数据」模块。下一步建议目标不是单纯补表单字段，而是让用户数据成为登录权限、产品组工作指引、建模排期、外包产能的可靠基础数据源。

```text

目标是让用户数据成为组织、账号、产能、建模能力、外包供应商的稳定数据源。
```

## 推荐下一步优先级

### P1：账号安全和用户状态收口

推荐先做这个，因为登录与权限已经上线，默认管理员和账号维护需要尽快更稳。

要做的能力：

- 用户数据页支持更清晰的重置密码流程。
- 支持设置 `mustChangePassword`。
- 默认管理员 `admin / admin123456` 登录后提示必须修改密码。
- 停用用户时，同步禁止登录。
- 用户列表明确显示：可登录、不可登录、必须改密、最近登录时间。
- 编辑用户时区分「人员信息」和「账号权限」两组字段。
- `authRole` 只能由 `admin` 修改。

边界：

- 不做忘记密码。
- 不做短信 / 邮件验证。
- 不做复杂单点登录。
- 不要在列表里显示密码明文。
- 重置密码只能显示一次初始密码，保存后只存 hash。

验收标准：

- admin 可以给用户设置登录名、角色、重置密码。
- viewer 不能访问用户写接口。
- 停用用户无法登录。
- 必须改密用户登录后有明确提示，哪怕第一版只是页面提醒。
- 用户数据页能看出谁有登录账号、谁没有。

### P1：产品组与人员归属正式化

产品组工作指引下一步要默认进入当前用户所在项目组，所以用户数据需要把产品组关系维护清楚。

要做的能力：

- 团队结构支持父子团队展示。
- 产品团队下面能看到四个项目组：易特凡组、忍者组、迪no组、丹东组。
- 每个项目组能设置组长 / 负责人。
- 人员详情能清晰展示所属团队、职位、是否产品研发、是否产品研发美术。
- 支持按项目组筛选人员。
- 支持在团队详情里查看该团队成员。
- 产品组成员信息能被产品组工作指引读取，用于默认项目组和负责人筛选。

边界：

- 不要把项目组写死在前端。
- 优先使用 `Team.parentTeamId` 表达父子团队。
- 优先使用 `Team.leaderUserId` 表达负责人。
- 如果现有 `roleTitle` 不足以区分产品研发 / 产品研发美术，先提出字段方案，不要直接大改 schema。

验收标准：

- `/users` 能看到产品团队下的四个项目组。
- 每个项目组能看到成员。
- 当前登录用户如果属于某个项目组，产品组工作指引后续可以读取到。
- 陶相帅能被标记为产品总监 / 易特凡组负责人。

### P1：建模师产能和能力标签补齐

建模排期下一步要做批量分配和超载判断，必须依赖用户数据里的建模师产能与能力。

要做的能力：

- 建模师列表单独筛选更清楚。
- 建模师每周产能 `weeklyCapacityStyles` 必填提示。
- 支持维护擅长类型和不擅长类型。
- 支持维护是否在职、是否可排期。
- 支持查看当前建模师在建模排期里的活跃任务数。
- 支持提示：缺少产能、缺少擅长类型、已停用但仍有任务。

边界：

- 超载规则仍由建模排期使用：排队款式数 > 4。
- 用户数据维护基础产能和能力标签，不直接改建模任务。
- 不要在用户数据里做复杂排期算法。

验收标准：

- 建模排期读取的建模师来自 `User.isModeler`。
- 没填产能的建模师在用户数据里有明显提示。
- 已停用建模师不应作为默认可分配对象。
- 建模师能力标签能在建模排期分配时展示或被读取。

### P1：外包供应商基础资料补齐

建模排期已经有外包中款式，但外包供应商目前还是占位口径。用户数据应维护供应商基础信息。

要做的能力：

- 外包供应商列表支持更清晰的启用 / 停用状态。
- 支持联系人、联系方式、擅长类型。
- 支持标记是否长期稳定外包。
- 支持维护外包可用产能的基础字段或备注。
- 建模排期选择外包供应商时，只读取启用供应商。

边界：

- 第一版不要做供应商财务结算。
- 第一版不要做复杂供应商评分。
- 如果需要数字化外包产能，而 `OutsourceVendor` 现有字段不够，先提出 schema 方案。

验收标准：

- `/users` 能维护真实供应商。
- 建模排期能读取启用供应商。
- 停用供应商不应作为默认可选对象。

### P2：人员名单批量导入

真实人员名单后续会继续变化，手动维护会越来越累。

要做的能力：

- 支持从 Excel / CSV 导入人员名单。
- 导入前展示预览。
- 按姓名或登录名匹配已有人员。
- 新人新增，离职 / 不在名单中的人员默认不删除，只建议停用。
- 不覆盖已有登录名、密码、权限角色。
- 对姓名冲突、团队不存在、职位为空给出提示。

边界：

- 不要导入时直接删除人员。
- 不要覆盖密码 hash。
- 不要覆盖人工修正过的姓名，除非用户确认。

验收标准：

- 能导入新版 HC 表。
- 导入前能看到新增、更新、建议停用的数量。
- 导入后用户数据页面刷新正常。

## 建议本轮不要做

- 忘记密码。
- 审计日志完整系统。
- 单点登录。
- 财务权限。
- 复杂组织审批流。
- 供应商结算。
- 复杂产能算法。
- 删除人员；继续使用停用。

## 关键业务规则

用户数据是基础数据源，可以维护：

- 人员名单。
- 团队结构。
- 登录账号。
- 权限角色。
- 建模师身份。
- 建模师周产能。
- 建模能力标签。
- 外包供应商。

用户数据不应该直接维护：

- 项目排期规划。
- 项目预测结果。
- 建模任务状态。
- 产品组工作指引任务状态。
- 财务测算结果。

权限规则：

```text
admin：可维护用户数据，可写业务数据
manager：不可维护用户数据，可写业务数据
viewer：只读
```
