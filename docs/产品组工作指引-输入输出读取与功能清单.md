# 产品组工作指引：输入、输出、读取与功能清单

更新时间：2026-05-31
模块：产品组工作指引
页面：`/product-guide`

## 1. 模块定位

产品组工作指引是产品研发 / 产品研发美术每天处理项目执行事实的入口。

它负责让产品组清楚看到：

- 当前项目组有哪些项目正在推进
- 本周要处理哪些任务
- 哪些任务有风险、阻塞或长时间未更新
- 哪些任务需要产品研发推进
- 哪些建模款式需要产品研发美术验收、送审或反馈
- 原画里程碑完成后，需要提交哪些建模款式资料

产品组工作指引不直接计算项目是否延期，也不直接维护建模排期。它只记录和提交执行事实，由项目排期和建模排期各自处理后续计算。

一句话边界：

> 产品组负责提交执行事实和款式基础资料；项目排期负责重算预测和风险；建模排期负责生成和维护款式级建模任务。

## 2. 四类边界定义

### 2.1 输入

输入指外部模块或人工主动提交给产品组工作指引的信息。

产品组工作指引收到输入后，可以创建待办、更新自己的展示状态，或触发后续操作入口。

输入不等于读取。其他模块提供的状态、列表、进度和统计，如果是产品组主动读取的，就归入“读取”，不归入“输入”。

### 2.2 输出

输出指产品组工作指引主动写回、通知或生成给其他模块使用的事实事件。

产品组工作指引输出的是执行事实，不输出项目风险结论，也不直接修改项目规划基线。

### 2.3 读取

读取指产品组工作指引主动从其他模块读取基础数据。

读取的数据只用于展示、聚合、筛选和辅助负责人判断，产品组工作指引不维护这些基础数据。

### 2.4 对外可读信息

对外可读信息指其他模块可以读取产品组工作指引维护的数据。

其他模块可以展示这些信息，但不应绕过产品组工作指引直接修改产品组侧的待办、处理记录或人工输入记录。

## 3. 当前核心功能

### 3.1 项目组工作页

每个项目组独立展示自己的工作页面。

产品组工作指引面向产品组展示的基础页面固定为五个：

| 基础页面 | 核心用途 |
| --- | --- |
| 产品规划视图 | 看本项目组项目在规划口径下，各月份、各里程碑应该完成什么 |
| 压力预测视图 | 看按当前执行进度测算，各项目里程碑预计会落到哪里 |
| 本周工作指引 | 看本周产品研发 / 产品研发美术应该处理哪些任务 |
| 项目明细 | 看单个项目的全部任务、进度、风险、建模摘要，并点击任务进入工作台 |
| 工作台 | 操作单个项目任务，录入完成、预计时间、阻塞、送审和建模相关动作 |

页面公共能力包含：

- 项目组切换
- 人员 / 风险筛选
- 项目点击进入项目明细
- 任务点击进入工作台处理
- 真实接口结果反馈

默认应该优先显示当前用户所在项目组，同时允许切换其他项目组。

正式 `/product-guide` 不展示原型、模拟器或联调模拟入口。测试工具只能保留在独立测试路由，不能进入产品组正式工作页导航。

### 3.2 产品规划视图

产品规划视图用于给产品组看“原本计划中，本组项目应该在哪个月完成哪些里程碑”。

产品规划视图读取项目排期的完整项目卡数据，不从工作指引事项反推。

产品规划视图使用规划月份：

```ts
card.plannedMonth ?? card.month
```

它应该展示项目组下所有项目的里程碑项目卡，而不是只展示风险项目或工作指引事项。

### 3.3 压力预测视图

压力预测视图用于给产品组看“按当前实际进度测算，本组项目的各里程碑预计会落到哪个月”。

压力预测视图同样读取项目排期的完整项目卡数据。

压力预测视图使用预测月份：

```ts
card.forecastMonth ?? card.month
```

产品规划视图和压力预测视图的项目落点可以不同。

### 3.4 本周工作指引

本周工作指引按项目组展示任务，当前主要分为：

- 本周需完成
- 本周在推进
- 本周要开始
- 风险任务
- 版权方反馈

任务列表优先保持简洁，核心字段为：

- 项目
- 任务
- DDL
- 延期线

点击任务后，进入该任务的工作台处理。

### 3.5 项目明细

项目明细是单个项目的执行事实与排期测算解释页。

它不是看板，而是产品组点进某个项目后，用来回答：

- 这个项目现在到底怎么样
- 为什么提醒我
- 为什么预测后移或产生风险
- 下一步应该由谁做什么
- 哪些任务需要补录事实或更新预计时间
- 哪些建模款式需要产品美术处理

项目明细用于承载详情，不应该把完整任务说明、测算解释和建模摘要全部塞进本周工作指引列表。

#### 3.5.1 项目基础信息

项目明细需要展示项目基础信息：

| 内容 | 说明 |
| --- | --- |
| 项目名称 | 产品组识别项目的主标题 |
| 项目 ID / 项目编号 | 系统项目 ID 必须保留，项目编号仅用于展示或辅助识别 |
| 项目组 | 当前项目所属项目组 |
| 产品研发 | 项目产品研发负责人 |
| 产品研发美术 | 项目产品研发美术负责人 |
| 版权方 | 当前项目版权方 |
| IP | 项目所属 IP |
| 产品类型 | 项目产品类型 |
| 项目状态 | 当前项目状态 |
| 预计上线月份 / 计划上线日期 | 项目计划上线节奏 |

当前页面读取 `Project` 主数据补齐版权方、IP、产品类型、项目组、产品研发和产品研发美术；如果主数据未填，只显示“待补充”，不能显示“项目排期未返回”作为业务字段。

#### 3.5.2 排期总览

项目明细需要展示项目排期总览：

| 内容 | 说明 |
| --- | --- |
| 规划上线时间 | 项目排期中的原计划上线时间 |
| 当前预测上线时间 | 排期内核测算后的预测上线时间 |
| 项目进度百分比 | 项目排期测算出的当前进度 |
| 当前任务 | 当前影响项目推进的任务 |
| 当前里程碑 | 当前项目所在里程碑 |
| 项目风险等级 | 从项目排期读取，不由产品组重新判断 |
| 风险说明 | 项目排期输出的风险文案 |
| 阻塞任务数 | 当前是否存在阻塞任务 |
| 超 3 天未更新任务数 | 当前是否存在长时间未更新任务 |

排期总览用于让产品组快速判断项目是否需要立即处理。

#### 3.5.3 规划 vs 压力预测

项目明细需要展示项目在规划视图和压力预测视图中的差异：

- 每个里程碑的规划月份
- 每个里程碑的预测月份
- 哪些里程碑后移
- 哪些里程碑提前
- 哪些里程碑已完成
- 哪些里程碑延期完成

这一部分用于解释项目为什么从产品规划视图移动到了压力预测视图中的另一个月份。

第一版可以只展示规划月份和预测月份；后续再增加“比规划晚几个月 / 提前几个月”的差异标签。

#### 3.5.4 项目任务列表

项目明细需要展示项目所有任务，而不是只展示当前任务。

任务列表字段建议包括：

| 字段 | 说明 |
| --- | --- |
| 任务编号 | 项目任务编号 |
| 任务名称 | 项目任务名称 |
| 所属里程碑 | 原画、建模、红蜡、平面、产前、大货等 |
| 负责人 | 当前任务负责人 |
| 计划完成日期 | 原计划完成日期 |
| 预计完成日期 | 当前预计完成日期 |
| 实际完成日期 | 任务已完成时的事实日期 |
| 当前状态 | 未开始、进行中、送审中、阻塞、暂停、已完成等 |
| 是否阻塞 | 是否存在阻塞 |
| 阻塞原因 | 阻塞说明 |
| 最近更新时间 | 判断是否超 3 天未更新 |
| 风险等级 | 从项目排期读取 |
| 排期测算提示 | 从排期测算结果读取的提示 |
| DDL | 当前任务应完成日期 |
| 延期线 | 晚于该日期会导致项目再次延期的边界 |

任务列表用于让产品组看到项目全貌，避免只处理当前提醒而忽略上下游任务。

项目明细中的每一条任务都必须是可点击的任务按钮。

点击任务后，不在项目明细里直接处理，而是进入该任务对应的工作台。

如果某项目少于 31 个标准任务，项目明细必须显示缺失任务编号，并提示“需由项目排期初始化确认，产品组不要手动补任务编号”。

#### 3.5.5 当前关键动作

项目明细需要明确当前项目的关键动作，但只做提示和入口，不直接承载完整操作表单。

关键动作可以包括：

- 当前需要产品研发推进什么
- 当前需要产品研发美术验收什么
- 当前是否等待版权方反馈
- 当前是否需要补录完成时间
- 当前是否需要更新预计完成时间
- 当前是否需要处理阻塞
- 当前是否需要补充建模款式清单

关键动作文案应该面向普通负责人，避免直接展示脚本状态。

示例：

- 请确认该任务是否已经完成，并补录实际完成时间。
- 该项目预测会延期，请确认当前卡点并更新预计完成时间。
- 该项目建模款式仍有未分配，请确认是否需要外包。
- 该款式卡在送审 / 修改，请产品美术确认下一步反馈。

#### 3.5.6 建模进度摘要

项目明细需要展示建模进度摘要。

摘要字段建议包括：

| 字段 | 说明 |
| --- | --- |
| 总款式数 | 项目建模款式总数 |
| 必做款式数 | 必须完成的款式数量 |
| 已通过款式 | 已版权方通过的款式数量 |
| 进行中款式 | 建模中、排队中、修改中的款式数量 |
| 待验收款式 | 建模师已提交，等待产品美术验收 |
| 待送审 / 已送审 / 等反馈款式 | 产品美术或版权方流程中的款式 |
| 未启动 / 未分配款式 | 尚未进入正式建模推进的款式 |
| 外包款式 | 当前外包中的款式 |
| 建模整体进度百分比 | 建模排期计算的项目建模进度 |

产品组只展示建模排期维护的数据，不直接修改建模状态。

#### 3.5.7 建模款式列表入口

项目明细需要提供建模款式列表入口。

款式列表至少展示：

- 款式名称
- 款式序号
- 是否第一款
- 是否必做
- 建模状态
- 建模师 / 外包供应商
- 最新反馈
- 修改轮次
- 内部通过日期
- 版权方过审日期
- 原画图 / 参考图
- 建模成果附件入口

如果建模排期输入了 `modeling_work_submitted`，项目明细应能进入对应款式的产品美术验收动作。

#### 3.5.8 最近进度记录

项目明细需要展示最近进度记录。

记录来源包括：

- 最近任务事实事件
- 最近备注
- 最近预计完成时间修改
- 最近阻塞 / 解除阻塞记录
- 最近送审记录
- 最近建模反馈事件
- 操作人
- 操作时间

最近进度记录用于帮助产品组判断“现在看到的状态是谁在什么时候更新的”。

#### 3.5.9 工作台入口

项目明细承载进入任务工作台的入口。

每条项目任务点击后进入工作台，工作台承载以下操作：

| 操作 | 输出对象 |
| --- | --- |
| 标记任务开始 | 项目排期 |
| 更新进度 | 项目排期 |
| 更新预计完成时间 | 项目排期 |
| 标记完成 | 项目排期 |
| 标记阻塞 | 项目排期 |
| 解除阻塞 | 项目排期 |
| 任务送审 | 项目排期 |
| 录入 / 补充建模款式清单 | 建模排期 |
| 建模成果审核 | 建模排期 |
| 送审结果录入 | 建模排期 |

本周工作指引只展示简要任务；项目明细展示项目全部任务；具体处理进入工作台完成。

#### 3.5.10 进入和返回

项目明细可以从以下页面进入：

- 产品规划视图点击项目卡
- 压力预测视图点击项目卡
- 本周工作指引点击项目或任务
- 工作台点击查看项目明细

项目明细应该支持返回：

- 返回产品规划视图
- 返回压力预测视图
- 返回本周工作指引
- 返回工作台
- 跳转建模排期

#### 3.5.11 项目明细不做的事

项目明细不做：

- 不重新计算项目预测
- 不直接修改风险等级
- 不直接修改里程碑落点
- 不替代建模排期维护建模状态
- 不直接维护建模师 / 外包供应商 / 产能
- 不把已完成项目误报为当前风险
- 不把历史延期完成当作当前风险

一句话定义：

> 项目明细是产品组查看单个项目全部任务、排期测算解释和建模摘要的页面；它读取项目排期和建模排期数据，每条任务点击后进入工作台处理。

### 3.6 工作台

工作台用于操作单个项目任务，同时承载外部模块回传给产品组的消息提醒。

工作台第一版拆成三个子页面：

| 子页面 | 用途 |
| --- | --- |
| 任务处理 | 操作单个项目任务，录入完成、预计时间、阻塞、送审等执行事实 |
| 消息提醒 | 存放建模排期、项目排期、版权、工厂等外部模块回传给产品组的通知 |
| 审批中心 | 处理建模成果已提交后的产品美术审批、内部通过、驳回、送审和送审结果录入 |

工作台应该回答：

- 我现在正在处理哪个项目、哪个任务
- 这个任务来自项目排期的哪条任务
- 这个任务的 DDL、延期线、预计完成和实际完成是什么
- 我现在可以执行哪些动作
- 这些动作会写回项目排期，还是提交给建模排期
- 其他部门是否有回传信息需要产品组处理
- 是否有建模成果需要产品研发美术审批

工作台可以展示：

- 任务队列
- 当前任务信息
- 任务操作按钮
- 操作后会产生的业务事件
- 与建模排期的联动提示
- 外部模块回传消息
- 审批中心待处理成果
- 返回项目明细、产品规划、压力预测、本周工作指引的入口

工作台任务队列必须读取项目排期任务清单：

- `ProjectTask`
- `ScheduleTaskResult`

如果项目排期没有返回任务，工作台应显示空队列和“项目排期当前没有返回任务清单”，不能使用前端原型自造任务补位。

每个任务的操作台也必须按真实任务编号加载配置，不能所有任务共用一套按钮。

原因：不同 `taskNo` 对应的操作台界面、必填表单、附件类型、业务事件和外部模块提交都不一样。任务如果不是项目排期返回的真实任务，产品组就可能进入错误的操作台，提交错误的事实事件或建模联动请求。

原型阶段也必须具备联调能力：关键按钮不能只改变前端状态，至少要调用本地真实接口，并在页面上展示请求内容、返回结果和失败原因。第一版联调接口包括：

- `POST /api/schedule/task-fact-events`
- `POST /api/modeling/style-submissions`
- `POST /api/modeling/style-start-events`
- `POST /api/modeling/review-results`
- `GET /api/modeling/projects/[projectId]/styles`
- `GET /api/modeling/projects/[projectId]/progress`
- `GET /api/modeling/product-guide-events`

原型数据必须优先使用 staging 当前真实数据库数据：

- 项目来自 `Project`
- 任务来自 `ProjectTask`
- 建模回传来自 `ModelingProductGuideEvent`
- 没有完整 `ScheduleTaskResult` 时，也不能把 `sample-schedule` 的样例项目混入页面
- 没有测算结果时，里程碑看板可由真实 `ProjectTask` 按项目 + 里程碑派生，页面需明确来源是 `ProjectTask 任务清单`

审批中心必须优先读取建模排期真实回传：

- `modeling_work_submitted` 进入审批中心
- 审批动作调用 `POST /api/modeling/review-results`
- 请求必须携带 `modelingTaskId`、`submissionFeedbackId` / `feedbackId`、`projectId`、`projectTaskId`
- 页面必须展示请求和返回，方便确认字段是否与建模排期契约一致

完整页面 `/product-guide` 必须展示真实接口结果，帮助少数产品组成员试用时确认写入是否成功：

- 点击本周工作指引任务后，右侧详情展示真实接口结果区域
- 标记完成、更新进度、更新预计时间、阻塞、解除阻塞、送审、提交款式清单、提交建模审核结果后，都要展示请求、返回、状态码和失败原因
- 正式页不展示“联调模拟”入口；原型页和测试台只用于讨论结构或管理员测试

第一版任务操作配置来源：

- `C:/Users/yuyou/Desktop/项目管理资料/任务处理.xlsx`

配置口径：

- `taskId` 对应项目排期任务编号 `taskNo`
- `taskName` 用于校验任务语义
- `操作1` 到 `操作10` 决定该任务工作台显示哪些动作
- 未配置的任务只能显示基础动作：开始、结束

示例：

| taskId | taskName | 操作 |
| --- | --- | --- |
| 1 | 市场调研 | 开始、结束、上传调研结果 |
| 3 | 项目企划 | 开始、结束、上传企划 pdf |
| 5 | 绘制款式效果图 | 开始、结束、上传效果图 png、启动建模款式表单填写 |
| 7 | 精细建模确认风格 | 开始、结束、上传渲染图 png |

工作台不重新计算排期，不直接判断风险，不展示项目全部任务全貌。

项目全貌在项目明细中查看，具体任务处理在工作台完成。

消息提醒用于集中承载其他模块回传，不应该把回传消息塞进任务操作卡片。

建模成果已提交属于审批类消息，点击后应该进入审批中心，不进入普通任务处理。

第一版消息提醒至少包含：

- 来源模块
- 消息类型
- 关联项目
- 关联任务
- 回传时间
- 消息摘要
- 未读 / 待处理 / 已处理状态
- 进入项目明细、任务处理或审批中心的入口

审批中心至少展示：

- 项目
- 关联任务
- 款式
- 建模任务 ID
- `submissionFeedbackId`
- `feedbackId`
- 审核轮次
- 建模成果附件
- 审批动作：内部通过可送审、内部不通过、已送审、等反馈、送审通过、送审不通过

审批中心只提交审批结果给建模排期，不直接维护建模状态。

### 3.7 任务事实录入

产品组可以在任务详情中录入任务执行事实。

支持动作包括：

- 标记开始 / 更新进度
- 更新预计完成时间
- 标记完成
- 标记阻塞
- 解除阻塞
- 记录送审
- 更新备注

这些动作会输出标准任务事实事件给项目排期。

### 3.8 建模款式清单录入

当原画里程碑完成后，产品组需要录入完整系列的建模款式清单。

款式清单至少包含：

- 款式序号
- 款式名称
- 是否必做
- 是否第一款建模款式
- 难度
- 预计建模天数
- 原画过审日期
- 原画图 / 参考图
- 备注

提交后，款式清单进入建模排期的确认流程。

### 3.9 建模启动通知

产品组任务启动时，需要通知建模排期启动对应款式。

当前规则：

- 任务 7 启动：启动第一款建模款式
- 任务 10 启动：启动其余建模款式
- 任务 8 / 9 不启动款式级建模任务

建模排期确认款式清单前，启动事件可能被拒绝。产品组页面应提示“任务事实已写入，但建模启动等待确认后补发”。

### 3.10 建模审核 / 送审结果

产品研发美术可以在产品组工作指引中处理建模成果。

允许提交：

- 内部通过可送审
- 内部不通过
- 已送审
- 等反馈
- 送审通过
- 送审不通过

内部不通过、送审不通过必须填写反馈内容。

审核结果会提交给建模排期，由建模排期维护建模状态、反馈记录和进度。

## 4. 输入

产品组工作指引当前接受两类输入：

- 人工输入
- 建模排期输入

其中，建模排期输入只包含建模排期主动提交给产品组工作指引的事实事件。

### 4.1 人工输入

产品组页面接受以下人工输入：

| 输入类型 | 说明 | 主要提交对象 |
| --- | --- | --- |
| 标记任务开始 | 任务进入进行中 | 项目排期 |
| 更新进度 | 填写当前进度、备注 | 项目排期 |
| 更新预计完成时间 | 填写新的预计完成日期 | 项目排期 |
| 标记完成 | 填写实际完成日期 | 项目排期 |
| 标记阻塞 | 填写阻塞原因和预计恢复 / 完成日期 | 项目排期 |
| 解除阻塞 | 填写解除说明和新的预计完成日期 | 项目排期 |
| 任务送审 | 填写送审日期、预计反馈日期、送审对象 | 项目排期 |
| 款式清单 | 填写完整系列款式资料 | 建模排期 |
| 任务 7 / 10 启动 | 通知建模排期启动对应款式 | 建模排期 |
| 建模审核 / 送审结果 | 产品美术提交内部审核或版权方结果 | 建模排期 |

### 4.2 建模排期输入

建模排期只会主动输入三种事件给产品组工作指引：

| 输入事件 | 中文含义 | 产品组工作指引处理 |
| --- | --- | --- |
| `style_list_confirmed` | 款式清单已确认 | 展示建模侧正式映射；后续审核、送审、读取状态优先使用 `modelingTaskId` |
| `style_list_returned` | 款式清单退回补充 | 生成“补充款式清单”待办；展示退回原因；允许产品组重新提交完整系列款式 |
| `modeling_work_submitted` | 建模成果已提交 | 生成“产品美术验收”待办；展示提交成果、附件、轮次和说明；审核时带最新 `submissionFeedbackId` / `feedbackId` |

不属于建模排期输入的内容：

- 款式状态列表不是输入，是读取
- 项目建模进度不是输入，是读取
- 建模师、外包供应商、产能、计时不是输入，是建模排期内部维护数据
- 普通建模状态变化不是输入，除非通过以上三种事件主动通知产品组工作指引

#### 4.2.1 `style_list_confirmed`

含义：

产品组提交的完整系列款式清单已经被建模排期确认。

产品组工作指引收到后应处理：

- 展示建模侧正式确认结果
- 保存或展示 `sourceStyleId -> modelingTaskId` 的正式映射
- 后续产品美术审核、送审、读取款式状态时优先使用 `modelingTaskId`
- 如果任务 7 / 10 已经开始，但建模排期此前因“待确认”拒绝启动，可以提示或补发建模启动事件

建议关键字段：

| 字段 | 说明 |
| --- | --- |
| `eventId` | 建模排期生成的事件 ID |
| `eventType` | `style_list_confirmed` |
| `projectId` | 系统项目 ID |
| `projectName` | 项目名称 |
| `projectTaskId` | 涉及的项目任务 ID |
| `styles` | 已确认的款式列表 |
| `sourceStyleId` | 产品组侧来源款式 ID |
| `modelingTaskId` | 建模排期正式建模任务 ID |
| `styleSequence` | 款式序号 |
| `styleName` | 款式名称 |
| `styleCode` | 款式编码 |
| `isFirstModelingStyle` | 是否第一款建模款式 |
| `isRequired` | 是否必做 |
| `modelingStatus` | 建模侧当前状态 |

#### 4.2.2 `style_list_returned`

含义：

建模排期认为产品组提交的款式清单信息不足，需要产品组补充。

产品组工作指引收到后应处理：

- 生成“补充款式清单”待办
- 展示退回原因
- 允许产品组重新打开完整款式清单
- 重新提交时必须提交完整系列，不能通过少传款式删除款式

建议关键字段：

| 字段 | 说明 |
| --- | --- |
| `eventId` | 建模排期生成的事件 ID |
| `eventType` | `style_list_returned` |
| `projectId` | 系统项目 ID |
| `projectName` | 项目名称 |
| `projectTaskId` | 涉及的项目任务 ID |
| `returnReason` | 退回原因 |
| `styles` | 被退回的款式列表 |
| `styleSubmissionBatchId` | 款式提交批次 |
| `styleSubmissionVersion` | 款式提交版本 |
| `generatedBy` | 退回操作人 |
| `occurredAt` | 退回时间 |

#### 4.2.3 `modeling_work_submitted`

含义：

建模师已经提交某个款式的建模成果，需要产品研发美术验收。

产品组工作指引收到后应处理：

- 生成“产品美术验收”待办
- 展示建模提交成果和附件
- 展示提交轮次、提交说明和提交人
- 产品美术提交审核结果时，必须带最新 `submissionFeedbackId` / `feedbackId`

建议关键字段：

| 字段 | 说明 |
| --- | --- |
| `eventId` | 建模排期生成的事件 ID |
| `eventType` | `modeling_work_submitted` |
| `projectId` | 系统项目 ID |
| `projectTaskId` | 项目任务 ID |
| `modelingTaskId` | 建模任务 ID |
| `sourceStyleId` | 产品组侧来源款式 ID |
| `styleCode` | 款式编码 |
| `styleSequence` | 款式序号 |
| `styleName` | 款式名称 |
| `modelingStatus` | 建模状态，通常为 `待验收` |
| `feedbackId` | 建模反馈 ID |
| `submissionFeedbackId` | 最近一次建模成果提交反馈 ID |
| `reviewRound` | 审核轮次 |
| `submittedWorkMinutes` | 本轮提交累计工时 |
| `deliverableUrls` | 建模成果附件 |
| `submissionSnapshot` | 建模侧提交快照 |
| `submittedAt` | 提交时间 |
| `submittedBy` | 提交人 |

款式清单字段建议固定为：

| 字段 | 说明 |
| --- | --- |

## 5. 输出给项目排期

产品组工作指引给项目排期输出标准任务事实事件：

接口：

```txt
POST /api/schedule/task-fact-events
```

事件名称：

```txt
ProjectTaskFactEvent
```

事件定位：

- 来源模块：`product-guide`
- 接收模块：`project-schedule`
- 用途：记录项目任务执行事实，作为排期内核重新测算的输入

最小字段：

```json
{
  "eventId": "uuid",
  "eventType": "task_completed",
  "sourceModule": "product-guide",
  "projectId": "系统项目ID",
  "taskNo": 7,
  "taskKey": "#7",
  "taskName": "精细建模确认风格",
  "occurredAt": "2026-05-29T10:30:00+08:00",
  "operatorId": "当前用户ID",
  "operatorName": "张三",
  "payload": {}
}
```

当前事件类型：

| 事件类型 | 含义 |
| --- | --- |
| `task_started` | 任务开始 |
| `task_expected_finish_updated` | 预计完成时间更新 |
| `task_submitted_for_review` | 任务进入送审中 |
| `task_completed` | 任务完成 |
| `task_blocked` | 任务阻塞 |
| `task_unblocked` | 任务解除阻塞 |
| `task_paused` | 任务暂停 |
| `task_resumed` | 任务恢复 |
| `task_note_updated` | 备注更新 |

产品组不输出以下结论：

- 风险等级
- 是否延期
- 预测上线日期
- 预测完成时间
- 里程碑状态
- 产能是否超载

这些都由项目排期和统一排期内核计算。

## 6. 输出给建模排期

### 6.1 款式清单提交

接口：

```txt
POST /api/modeling/style-submissions
```

用途：

产品组在原画里程碑完成后，提交完整系列款式清单。

建模排期接收后：

- 创建 / 更新 `ModelingTask`
- 新建状态为 `待确认`
- 不代表建模已启动
- 不进入正式产能计算
- 等待建模侧确认或退回补充

### 6.2 款式启动事件

接口：

```txt
POST /api/modeling/style-start-events
```

任务 7 启动：

```json
{
  "taskNo": 7,
  "startScope": "first-style"
}
```

任务 10 启动：

```json
{
  "taskNo": 10,
  "startScope": "remaining-styles"
}
```

建模排期处理：

- 任务 7：第一款 `未启动 -> 未分配`
- 任务 10：其余款 `未启动 -> 未分配`
- 任务 8 / 9 会被拒绝
- `待确认` / `退回补充` 状态不能启动

### 6.3 建模审核 / 送审结果

接口：

```txt
POST /api/modeling/review-results
```

允许结果：

| 产品组提交结果 | 建模排期状态变化 |
| --- | --- |
| 内部通过可送审 | `待验收 -> 待送审` |
| 内部不通过 | `待验收 -> 排队中` |
| 已送审 | `待送审 -> 已送审` |
| 等反馈 | `待送审 / 已送审 -> 等反馈` |
| 送审通过 | `待送审 / 已送审 / 等反馈 -> 已通过` |
| 送审不通过 | `待送审 / 已送审 / 等反馈 -> 排队中` |

反馈要求：

- 内部不通过必须填写文字反馈
- 送审不通过必须填写文字反馈
- 通过类可以不填文字，但允许附件

## 7. 读取

读取指产品组工作指引主动从其他模块读取的数据。读取的数据用于展示、聚合、筛选和辅助负责人判断，不代表外部模块主动输入给产品组。

### 7.1 读取项目排期

产品组工作指引读取项目排期，核心目的不是重新计算排期，而是把项目排期已经计算好的规划、预测、任务风险和关键动作，转成产品组每天能看的工作页面。

这部分全部属于“读取”，不属于“输入”。

产品组工作指引从项目排期读取以下数据：

| 读取内容 | 说明 | 用途 |
| --- | --- | --- |
| 项目基础排期 | 项目 ID、项目名称、项目组、产品研发、产品研发美术、计划上线日期、当前阶段、项目状态 | 确定项目属于哪个项目组、由谁负责、计划节奏是什么 |
| 项目任务清单 | `ProjectTask`，包含任务编号、任务名称、所属里程碑、负责人、计划完成日期、预计完成日期、实际完成日期、任务状态、阻塞信息、最近更新时间 | 构建任务详情、本周工作指引和项目分析 |
| 项目排期测算结果 | `ScheduleProjectResult`，包含项目预测、当前任务、项目风险、项目进度、阻塞任务数、长时间未更新任务数 | 判断哪些项目需要产品组关注 |
| 任务排期测算结果 | `ScheduleTaskResult`，包含任务预测完成日期、风险等级、风险文案、计划完成日期、延期天数、任务状态 | 判断哪些任务进入本周工作指引 |
| 项目排期里程碑卡 | `ProjectCard`，包含项目名称、里程碑、规划月份、预测月份、风险颜色 | 展示项目组里程碑规划视图和压力预测 |
| 项目排期提醒 | 项目风险、任务风险、延期风险、必然延期、阻塞、超 3 天未更新、版权方反馈相关提醒 | 生成风险任务和版权方反馈模块 |

#### 7.1.1 项目基础排期

产品组工作指引需要读取项目基础排期字段：

- 项目 ID
- 项目名称
- 项目组
- 产品研发
- 产品研发美术
- 计划上线日期 / 月份
- 当前项目阶段
- 项目状态

这些字段用于确定：

- 项目属于哪个项目组
- 项目应该显示在哪个项目组页面
- 谁是产品研发负责人
- 谁是产品研发美术负责人
- 项目计划上线节奏
- 项目是否已完成或不应进入当前待处理

#### 7.1.2 项目任务清单

产品组工作指引需要读取项目任务：

- 任务 ID
- 任务编号
- 任务名称
- 所属里程碑
- 任务负责人
- 计划完成日期
- 预计完成日期
- 实际完成日期
- 任务状态
- 是否阻塞
- 阻塞原因
- 进度备注
- 最近更新时间

这些字段用于：

- 展示任务详情
- 生成本周需完成任务
- 生成本周在推进任务
- 生成本周要开始任务
- 判断任务是否超过 3 天未更新
- 判断任务是否已经完成，不误报当前风险

#### 7.1.3 项目排期测算结果

产品组工作指引读取 `ScheduleProjectResult`。

主要用于知道：

- 当前项目预测是否延期
- 当前项目风险等级是什么
- 当前项目正在卡在哪个任务
- 项目当前进度百分比
- 项目是否存在阻塞任务
- 项目是否存在长时间未更新任务
- 项目风险文案是什么

产品组只展示或转译这些结果，不直接修改这些结果。

#### 7.1.4 任务排期测算结果

产品组工作指引读取 `ScheduleTaskResult`。

主要用于知道：

- 哪些任务在关键路径
- 哪些任务本周必须处理
- 哪些任务已经有延期风险
- 哪些任务预测完成时间晚于计划完成时间
- 哪些任务会影响上线节奏
- 任务的 DDL 和延期线

产品组工作指引可以基于这些结果生成工作指引，但不自己判断最终延期结论。

#### 7.1.5 里程碑看板数据

产品组工作指引读取项目排期生成好的完整 `ProjectCard`。

它不从工作指引事项重新推导里程碑，也不只展示风险项目。

里程碑顺序：

```ts
[
  "原画里程碑",
  "建模里程碑",
  "红蜡里程碑",
  "平面里程碑",
  "产前里程碑",
  "大货里程碑",
```

```ts
card.plannedMonth ?? card.month
```

#### 7.1.6 读取后生成的五个基础页面

读取项目排期后，产品组工作指引主要生成五个基础页面：

| 基础页面 | 来源 | 说明 |
| --- | --- |
| 产品规划视图 | 项目排期 `ProjectCard.plannedMonth` | 看本项目组原计划中，各项目里程碑应该落在哪个月 |
| 压力预测视图 | 项目排期 `ProjectCard.forecastMonth` | 看按当前进度测算，各项目里程碑预计会落在哪个月 |
| 本周工作指引 | `ProjectTask` + `ScheduleTaskResult` + `ScheduleProjectResult` | 展示本周需完成、本周在推进、本周要开始、风险任务、版权方反馈 |
| 项目明细 | `Project` + `ProjectTask` + `ScheduleProjectResult` + `ScheduleTaskResult` | 展示单个项目全部任务、测算结果、风险原因和建模摘要；任务点击进入工作台 |
| 工作台 | `ProjectTask` + `ScheduleTaskResult` + 外部模块回传消息 | 操作单个项目任务；消息提醒集中展示回传通知；审批中心处理建模成果审批 |

本周工作指引内部再分为：

- 本周需完成
- 本周在推进
- 本周要开始
- 风险任务
- 版权方反馈

项目明细用于承载项目全貌，不应把完整任务说明、测算解释和建模摘要全部塞进本周工作指引列表。

工作台用于承载单个任务的处理动作，不应该由项目明细直接完成任务操作。

工作台的消息提醒子页用于承载其他模块回传通知，不限于建模排期。

建模成果已提交这类消息应进入审批中心，不进入任务处理。

工作台任务队列不能使用原型虚构任务。任务行必须由项目排期的 `ProjectTask` 和 `ScheduleTaskResult` 转换得到。

#### 7.1.7 产品组不能直接改的项目排期数据

产品组工作指引不能直接修改：

- `ScheduleProjectResult`
- `ScheduleTaskResult`
- 项目风险等级
- 预测上线日期
- 预测完成日期
- 压力预测结果
- 里程碑状态
- 项目是否延期的结论

如果产品组发现实际情况变化，应通过人工输入输出任务事实事件：

```txt
ProjectTaskFactEvent -> 项目排期 -> 排期内核重算
```

一句话总结：

> 产品组读取项目排期，是为了知道“现在该看什么、该处理什么、风险在哪里”；但产品组不维护排期结论，只把人工确认的执行事实写回项目排期，让排期内核重新计算。

## 8. 对外可读信息

当前产品组工作指引本身主要是“写入口”和“聚合展示页”。其他模块真正读取的是它提交出去的标准事实。

### 8.1 项目排期可读取

项目排期读取产品组提交的任务事实事件，并落到项目任务事实字段：

- 任务状态
- 实际开始日期
- 实际完成日期
- 预计完成日期
- 是否阻塞
- 阻塞原因
- 进度备注
- 送审日期
- 操作人
- 原始事件 payload

项目排期用这些事实触发或标记重算。

### 8.2 建模排期可读取

建模排期读取产品组提交的建模相关事实：

- 完整系列款式清单
- 第一款建模款式标记
- 原画图 / 参考图链接
- 原画过审日期
- 预计建模天数
- 任务 7 启动事件
- 任务 10 启动事件
- 产品美术审核结果
- 版权方送审 / 反馈结果

建模排期用这些事实生成和维护款式级建模任务。

### 8.3 管理看板后续可读取

后续如果做管理看板，可以读取或聚合：

- 产品组提交任务事实的频率
- 超 3 天未更新任务数量
- 阻塞任务数量
- 建模款式清单提交状态
- 建模退回补充次数
- 产品美术待验收数量
- 版权方反馈等待数量
- 每个项目组当前工作量

## 9. 产品组不能做的事
