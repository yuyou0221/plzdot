# 下一步任务上下文-建模排期

最后更新：2026-05-25

这份文档用于新对话继续推进「建模排期」。本轮建议目标不是重做页面，而是让基础版从“能看”升级到“能真正排、能批量处理、能提示回写”。

## 新对话使用方式

新对话开始时建议直接发：

```text
请阅读 docs/项目管理平台-当前总控上下文.md
请阅读 docs/模块交接总结-建模排期基础版.md
请阅读 docs/下一步任务上下文-建模排期.md

本轮只处理建模排期，不处理产品组工作指引大改、项目排期大重构、财务、知识库、权限登录和送审 AI。
目标是补齐建模排期基础版的批量分配、供应商、款式详情和项目排期回写提示。
```

## 当前基础版状态

已完成：

- `/modeling` 页面和侧边栏入口。
- 顶部视图包括 `里程碑`、`管理层看板`、`款式看板`、`个人信息`。
- 默认进入 `里程碑` 视图。
- 建模里程碑读取项目排期任务 `7-10`。
- 真实 `ModelingTask` 优先展示，没有真实款式时才生成虚拟款式。
- 虚拟款式明确标注，且不能保存到数据库。
- 真实款式支持拖拽分配建模师、改状态、标记外包、记录反馈。
- 已通过款式不出现在活跃排期列表。
- 个人信息页当前用建模师下拉模拟登录用户。

当前没做：

- 批量分配。
- 外包供应商选择。
- 批量状态更新。
- 修改轮次管理。
- 完整送审反馈流程。
- 所有必做款式通过后的项目任务回写提示。
- 触发项目预测重新测算。
- 管理层看板权限。

## 推荐下一步优先级

### P1：批量分配和批量状态更新

推荐先做这个，因为当前仍有大量活跃款式未分配。没有批量能力，真实使用会很累。

要做的能力：

- 款式看板支持多选。
- 支持批量分配给某个建模师。
- 支持批量标记外包。
- 支持批量修改状态，例如未分配 -> 已排期、已排期 -> 建模中。
- 支持批量设置计划开始 / 计划完成日期。
- 操作前显示确认摘要：影响多少款、哪些项目、哪些建模师。
- 操作后刷新建模师任务数量、超载提示、项目建模进度。

边界：

- 只能对真实 `ModelingTask` 批量操作。
- 虚拟款式不能批量保存。
- 已通过款式默认不参与批量修改，除非明确进入已通过页签做修正。
- 批量操作不能修改项目排期规划基线。

验收标准：

- 能一次选择多个未分配款式并分配给同一个建模师。
- 分配后刷新页面仍然保留。
- 超载规则 `排队款式数 > 4` 正确提示。
- 批量外包后进入外包分组。
- 虚拟款式不会被错误写入数据库。

### P1：外包供应商与外包状态补齐

当前外包供应商还是占位口径。建模排期如果要辅助真实排期，需要知道哪些外包由谁承接。

要做的能力：

- 款式详情中选择外包供应商。
- 外包分组按供应商二级分组。
- 供应商为空时显示「待补充供应商」。
- 能按供应商筛选外包款式。
- 外包款式仍参与项目建模进度。
- 外包款式不计入内部建模师超载，但要计入外包负载。

边界：

- 外包供应商基础数据来自用户数据模块 `OutsourceVendor`。
- 不要在建模排期里创建复杂供应商档案；最多允许选择已有供应商或保留待补充。
- 长期稳定外包是否算内部产能，后续由用户数据模块维护。

验收标准：

- 外包款式可以选择供应商。
- 外包分组能看出每个供应商有多少款。
- 内部建模师超载不统计外包款式。

### P1：款式详情和反馈轮次

建模排期最容易出错的是送审、等反馈、修改。下一步需要把这些状态记录得更清楚。

要做的能力：

- 款式详情展示项目、款式名、建模师、状态、是否外包、供应商、实际开始、实际完成、最后更新。
- 支持新增反馈记录。
- 反馈记录包含：反馈类型、反馈内容、提出人、反馈日期、是否已处理。
- 状态切到 `已送审` 时记录送审时间。
- 状态切到 `等反馈` 时记录等待开始时间。
- 状态从 `等反馈` 回到 `建模中` 时记录修改开始。
- 状态切到 `已通过` 时写入实际完成时间。

边界：

- 第一版不用做复杂审批流。
- 第一版不用接版权方送审 AI。
- 反馈轮次先记录事实，不做自动判断对错。

验收标准：

- 每次反馈能保存并刷新后仍可见。
- 长时间未更新提醒能基于最后更新时间判断。
- 已通过款式有实际完成日期。

### P1：项目任务回写提示

当前所有必做款式通过后，还没有自动回写项目任务「根据效果图建模」。下一步建议先做“提示 + 确认”，不要静默自动回写。

要做的能力：

- 项目级建模进度判断：所有必做真实款式已通过。
- 达成条件时显示「可回写项目建模任务完成」提示。
- 点击确认后，回写项目任务「根据效果图建模」实际完成日期。
- 实际完成日期 = 最后一款必做款式通过日期。
- 回写后提示「需要重新测算项目排期」。

边界：

- 不要自动改项目规划视图。
- 不要自动推迟项目计划上线日期。
- 不要静默回写，必须有用户确认。
- 如果存在必做款式未通过，不能回写项目任务完成。
- 如果只有虚拟款式，不能回写项目任务完成。

验收标准：

- 全部必做款式通过后出现回写提示。
- 未全部通过时不出现回写提示。
- 确认回写后，项目任务 10 有实际完成日期。
- 回写后项目排期页面能提示需要重新测算，或至少能看到执行事实已更新。

## 建议本轮不要做

- 权限登录。
- AI 送审检查。
- 财务联动。
- 完整产能算法大重构。
- 项目排期规划视图编辑。
- 产品组工作指引大改。
- 自动静默回写项目排期。

## 关键业务规则

建模排期可以写款式状态，但不能改规划。

建模排期允许写入：

- 建模师分配。
- 外包状态。
- 外包供应商。
- 建模状态。
- 实际开始 / 完成日期。
- 反馈记录。
- 项目建模进度。

建模排期不允许直接写入：

- 项目计划上线日期。
- 项目路线。
- 项目等级。
- 规划里程碑月份。

项目排期里的「根据效果图建模」完成规则：

```text
如果项目存在必做真实 ModelingTask：
  所有必做款式 = 已通过
  → 可提示回写 ProjectTask “根据效果图建模” 已完成
  → 实际完成日期 = 最后一款通过日期
  → 标记需要重新测算

如果还有任意必做款式未通过：
  项目建模任务不能算完成

如果只有虚拟款式：
  不能回写项目建模任务完成
```
