# 下一步任务上下文-建模排期

最后更新：2026-05-31

这份文档用于新对话继续推进「建模排期」。当前口径已经调整为：建模排期是款式级建模子系统，负责接收款式输入、推进款式建模、记录工时与反馈，并向产品组和项目排期提供事实；建模排期不主动回写项目排期，不修改项目规划基线，不修改项目计划上线日期。

## 新对话使用方式

新对话开始时建议直接发：

```text
请先阅读：
docs/项目管理平台-当前总控上下文.md
docs/模块开发边界上下文.md
docs/建模排期模块-输入输出读取与功能清单.md
docs/下一步任务上下文-建模排期.md

本轮只处理建模排期模块，不处理财务、知识库、权限登录、送审 AI、项目排期大重构和产品组工作指引大改。

当前建模排期边界：
- 建模排期负责 ModelingTask 款式级建模事实。
- 产品组工作指引提交款式基础资料、任务 7/10 启动事件、审核/送审结果。
- 建模排期只向产品组输出主动事件，不主动输出给项目排期。
- 项目排期只主动读取建模完成事实，建模排期不写 ProjectTask。
- 用户数据是建模师、产能、稳定外包供应商的读取来源。
```

## 当前已完成

- `/modeling` 页面和侧边栏入口。
- `/modeling` 顶部只保留 `里程碑`、`款式看板`、`个人信息`。
- 独立管理层看板已移除；管理层统计后续归入“对外可读信息”，不作为当前独立页面。
- 默认进入 `里程碑` 视图，显示本月、之前未完成、下月建模里程碑。
- 建模里程碑读取项目排期任务 `7-10`。
- 真实 `ModelingTask` 优先展示；没有真实款式时才生成虚拟款式。
- 虚拟款式明确标注，且不能保存到数据库。
- 款式看板按人分组，未分配单独显示。
- 已通过款式不出现在活跃排期列表；`已通过款式` 入口在款式看板内部。
- 个人信息页可查看某个建模师自己的建模款式，当前仍用下拉模拟当前用户。
- 款式详情支持查看累计工时、反馈次数、最新提交成果、检修 / 送审记录。

## 已完成的输入闭环

### 1. 款式清单提交与建模确认

- 产品组或模拟器提交系列级款式清单后，款式进入 `待确认`。
- 提交后生成建模排期专属待办：`款式清单待确认`。
- 待办打开同一张系列款式清单页，不再逐款拆成多个确认页。
- 建模侧可整批确认，确认后全部进入 `未启动`。
- 建模侧可整批退回补充，退回必须填写原因，并写入反馈记录。
- 退回后可重新提交完整系列。
- 重新提交如果缺少原系列款式会被拒绝，不能靠缺失静默删除款式。
- 每次提交记录 `styleSubmissionBatchId` 和 `styleSubmissionVersion`。
- 确认后会返回给产品组程序保存映射用的正式款式级任务清单，包括 `modelingTaskId`、`sourceStyleId`、`projectTaskId`、`taskNo`、款式序号、款式名、是否第一款、是否必做和当前状态。
- `FIX-...`、`LOCAL-...`、`RESUBMIT-...`、`fixture-...` 等测试字段仅 `admin` 可见。

### 2. 任务 7 / 任务 10 启动事件

- 任务 7 只启动第一款：`未启动 -> 未分配`。
- 任务 10 只启动其余款式：`未启动 -> 未分配`。
- 任务 8 / 9 会被拒绝，不产生款式级建模任务。
- `待确认`、`退回补充` 款式不能启动。
- 重复启动保持幂等，并返回启动 / 跳过摘要。
- 启动事件只改变款式状态，不分配建模师，不开始计时，不修改项目排期规划基线。

### 3. 产品审核 / 送审结果

- 建模师提交成果后，款式进入 `待验收`。
- 产品审核 / 送审结果当前已通过建模页内模拟器和 `/modeling` 详情区验证。
- 内部通过可送审：`待验收 -> 待送审`。
- 内部不通过：`待验收 -> 排队中`，必须填写文字反馈。
- 已送审：`待送审 -> 已送审`。
- 等反馈：`待送审 / 已送审 -> 等反馈`。
- 送审通过：`待送审 / 已送审 / 等反馈 -> 已通过`。
- 送审不通过：`待送审 / 已送审 / 等反馈 -> 排队中`，必须填写文字反馈。
- 通过类和过程类可以不填文字反馈，但允许图片 / PDF / PPT 反馈链接。
- 审核必须锁定最新一次建模成果提交，旧提交记录不能被审核。

## 已完成的建模侧能力

- 单款分配建模师。
- 单款标记外包。
- 外包状态保存，状态由系统自动推进到 `外包中`。
- 建模状态只读展示，不提供手动状态推进。
- 建模师可点击开始建模计时。
- 同一建模师开始另一款时，系统自动停止上一款计时。
- 建模师提交成果时，系统自动停止本款计时。
- 建模工时按分钟累计，并写入 `ModelingWorkLog`。
- 建模师分配 / 外包切换写入 `ModelingAssignmentHistory`。
- 计时显示按 5 分钟刷新，开始、自动停止、提交后立即刷新。
- 款式看板已移除全选和多选，只保留单款详情与单款操作。
- 管理侧取消款式事件已存在。
- 管理侧已通过款式重开事件已存在，重开后回到 `排队中`。

## 当前主动输出事件

建模排期只主动输出给产品组工作指引三个事件：

| 事件 | 触发时机 |
| --- | --- |
| `style_list_confirmed` | 建模侧确认款式清单 |
| `style_list_returned` | 建模侧退回款式清单 |
| `modeling_work_submitted` | 建模师提交成果，款式进入 `待验收` |

说明：

- `modeling_project_all_approved` 不作为主动输出事件。
- 项目必做款式全部通过属于对外可读完成事实，由项目排期主动读取。
- 产品组如果没有接住接口返回，可以通过 `GET /api/modeling/product-guide-events` 补读事件。

## 项目排期读取口径

当前已经稳定 `GET /api/modeling/projects/[projectId]/progress`，给项目排期读取建模事实。

固定统计范围：

```text
任务 7 + 任务 10 的所有必做建模款式
```

关键字段：

- `sourceTaskNos = [7, 10]`
- `allRequiredStylesApproved`
- `canProjectScheduleTreatModelingDone`
- `requiredStyleCount`
- `approvedRequiredStyleCount`
- `lastRequiredStyleApprovedDate`
- `unapprovedRequiredStyles`
- `blockingStyles`
- `submittedOrWaitingStyles`

边界：

- 建模排期不主动写 `ProjectTask`。
- 建模排期不生成“确认回写”按钮。
- 建模排期不修改项目任务实际完成日期。
- 建模排期不触发项目排期重新测算。
- 项目排期后续自己读取这些事实，并决定是否把建模视为完成、是否重新测算。

## 关键业务规则

建模排期可以写：

- `ModelingTask.modelerId`
- `ModelingTask.isOutsourced`
- `ModelingTask.outsourceVendorId`
- 款式计划开始 / 完成
- 款式实际开始 / 完成
- `remainingWorkdays`
- `actualWorkMinutes`
- `activeWorkStartedAt`
- 款式状态
- `ModelingFeedback`
- `ModelingWorkLog`
- `ModelingAssignmentHistory`
- `ModelingProductGuideEvent`

建模排期不允许写：

- 项目计划上线日期
- 项目路线
- 项目等级
- 规划里程碑月份
- 项目排期规划基线
- 项目排期整体预测结果
- `ProjectTask` 完成事实

项目排期里的“根据效果图建模”完成判断：

```text
如果项目存在任务 7 / 10 的必做真实 ModelingTask：
  所有必做款式 = 已通过
  → GET /api/modeling/projects/[projectId]/progress 返回 allRequiredStylesApproved = true
  → 返回 canProjectScheduleTreatModelingDone = true
  → 返回 lastRequiredStyleApprovedDate = 最后一款必做款式通过日期

如果还有任意任务 7 / 10 必做款式未通过：
  allRequiredStylesApproved = false
  canProjectScheduleTreatModelingDone = false

如果只有非必做款式未通过：
  不阻塞必做建模完成事实

如果只有虚拟款式：
  不能被项目排期读取为真实建模完成事实
```
