## 本轮目标

修复网页端排期内核 V5 的日期语义：

- `planned` 不再承载上线日期倒推出来的最晚安全日期。
- `planned` 改为从 `projectStartDate` 正推得到的管理计划。
- `latest` 表示从原计划上线日期倒推得到的最晚安全线。
- `currentLatest` 表示从当前预测上线日期倒推得到的动态最晚安全线。
- `calculated` 表示基于 planned 和实际进度事实保守传播后的当前预测日期。
- `actual` 表示真实执行事实，实际完成日期覆盖本任务的 calculated 完成日期。

## 本轮完成内容

- `plannedStartDate` / `plannedFinishDate` 现在来自 `projectStartDate` 正推。
- `latestStartDate` / `latestFinishDate` 现在来自 `effectiveLaunchDate` 倒推。
- `currentLatestStartDate` / `currentLatestFinishDate` 现在来自 `projectedLaunchDate` 倒推。
- `currentDdlDate` 保留兼容，但语义等价于 `calculatedFinishDate`。
- 新增 / 输出 `currentDeadlineRiskDays`，用于区分是否继续影响当前预测上线。
- 缺少 `projectStartDate` 的项目不再使用 `plannedLaunchDate - 180 天` 生成假 planned，而是进入测算 warning/error。
- 空 `remainingDays` 不再按 0 处理。
- 未开始、未完成、无 remainingDays 且预测完成日已在过去的任务，会按 `max(原 calculatedStartDate, today) + 标准工期` 保守预测。
- 未完成任务即使有 `expectedFinishDate`，只要该预计完成日早于 today，也不会把它作为最终 `calculatedFinishDate`。
- `actuals` 多记录聚合改为按 `updatedAt` / `rowUpdatedAt` / `createdAt` 判断新旧，并按字段取最新非空事实。
- `taskName` 不再是 actual 匹配的最低必要条件；只要 `projectId + taskId/taskNo` 能确认任务，就保留 actual，缺任务名时从任务规则回填。
- `impactStatus` 区分：
  - 正常
  - 落后计划未影响上线
  - 影响上线
  - 继续影响当前上线
  - 已完成
  - 已完成-晚于计划
  - 已完成-影响上线
- 实际进度匹配优先使用 `recordKey` / 显式 `projectId`，项目名称只作为 fallback，并写入 warning 统计。
- 项目排期任务表增加 currentLatest/currentDeadline 字段展示，调整旧“当前 DDL / 再次延期”文案，避免继续误导。

## 排期内核变化

planned 口径：`projectStartDate` 正推。

latest 口径：`effectiveLaunchDate` 倒推。

currentLatest 口径：`projectedLaunchDate` 倒推。

calculated 口径：`planned + actuals + remainingDays + 前置任务 calculated` 保守传播。

actuals 匹配口径：优先 `recordKey` / `projectId + taskId/taskNo`，项目名称 fallback 进入 warning。

actuals 多记录聚合口径：

- 数据库输入层 `project-analysis-v5-input.ts` 从 `ProjectTask` 读取快照；`ProjectTask` 在 `prisma/schema.prisma` 中有 `@@unique([projectId, taskNo])`，因此数据库正式输入天然是每个项目每个任务一条 snapshot。
- 但 Excel / 脚本直接输入不能保证唯一，所以内核层仍做防御。
- 同项目同任务多条 actual 先按 `updatedAt` / `rowUpdatedAt` / `createdAt` 判断新旧。
- 再按关键字段取最新非空事实：`actualStartDate`、`actualFinishDate`、`expectedFinishDate`、`remainingDays`、`taskStatus`。
- 这样既不会被旧 `actualStartDate` 排序误导，也不会让新空值覆盖旧真实事实。

taskName 口径：

- 数据库输入层一定传 `taskName`，因为 `ProjectTask.taskName` 是必填字段。
- 内核层不再要求 `taskName` 必填；`projectId + taskId/taskNo` 是实际进度匹配的最低必要条件。
- 缺少 `taskName` 时，会从任务规则回填任务名。

remainingDays 空值处理：空值表示未填写，不等于 0。

未完成逾期任务处理：不再预测在过去；无剩余天数时按 today 起重新加标准工期；过期 `expectedFinishDate` 不作为最终预测完成日。

节假日处理：沿用既有 core engine 规则，本轮未修改节假日算法。
