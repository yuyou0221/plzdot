## 新一轮目标

把产品组工作指引从「只读展示页面」升级为：

```text
产品负责人 / 产品研发美术每天处理任务、写进度、录入款式清单的执行入口。
```

本轮仍不做：

- 财务
- 知识库完整系统
- 权限登录
- 送审 AI
- 项目排期大重构

## 核心原则

```text
产品组工作指引可以写执行事实，但不能改规划基线。
```

它可以写数据，但写入的是已有业务表：

- `ProjectTask`
- `ProgressUpdate`
- `ModelingTask`
- 必要时读取 / 更新 `ProjectModelingProgress`

它不应该维护一套独立的待办状态。动作是否存在，应由底层事实自动决定。

## 系统关系

```text
项目排期输出预测结果
→ 产品组工作指引生成动作清单
→ 产品负责人 / 产品美术写入执行事实
→ 项目排期标记需要重新测算
→ 重新测算后更新预测视图
```

款式链路：

```text
项目排期出现建模窗口
→ 产品组工作指引提示录入款式清单
→ 产品负责人创建 ModelingTask
→ 建模排期出现未分配款式
→ 建模排期推进款式状态
→ 所有必做款式已通过
→ 回写 ProjectTask “根据效果图建模”完成
→ 项目排期重新测算
```

## 允许写入的动作

### 标记任务已完成

写入：

```text
ProjectTask.status = 已完成
ProjectTask.actualFinishDate = 实际完成日期
ProjectTask.lastUpdatedAt = 当前时间
ProjectTask.lastUpdatedBy = 当前操作人
ProgressUpdate 新增一条记录
```

要求：

- 实际完成日期必填
- 默认是今天
- 可以手动修改
- 可填写备注

保存提示：

```text
已记录完成时间。该项目需要重新测算，预测视图将在重新测算后更新。
```

### 更新预计完成日期

写入：

```text
ProjectTask.expectedFinishDate
ProjectTask.progressNote
ProjectTask.lastUpdatedAt
ProjectTask.lastUpdatedBy
ProgressUpdate
```

要求：

- 预计完成日期必填
- 备注建议填写，第一版可不强制

### 标记任务阻塞

写入：

```text
ProjectTask.isBlocked = true
ProjectTask.blockReason
ProjectTask.progressNote
ProjectTask.lastUpdatedAt
ProjectTask.lastUpdatedBy
ProgressUpdate
```

要求：

- 阻塞原因必填

保存提示：

```text
已记录阻塞原因。该任务会继续出现在工作指引和管理层提醒中。
```

### 解除阻塞

写入：

```text
ProjectTask.isBlocked = false
ProjectTask.progressNote
ProjectTask.lastUpdatedAt
ProjectTask.lastUpdatedBy
ProgressUpdate
```

是否清空 `blockReason` 可以后续决定；第一版可以保留历史备注，不必物理清空。

### 录入款式清单

写入：

```text
ModelingTask
```

每个款式至少包含：

```text
projectId
projectTaskId = 对应“根据效果图建模”任务
styleCode
styleName
isRequired
originalArtStatus
difficulty
estimatedWorkdays
status = 未分配
affectsProjectSchedule = true
```

要求：

- 款式数量或款式名称必填
- 没有真实名称时允许「款式 1 / 款式 2」，但要标记为待补充
- 产品负责人可以先创建
- 产品研发美术后续补原画过审信息

保存提示：

```text
已生成 X 个建模款式，建模排期中将显示为未分配。
```

### 标记原画过审

写入：

```text
ModelingTask.originalArtStatus = 已过审
ModelingTask.originalArtApprovedDate
ModelingTask.lastUpdatedAt
ModelingTask.lastUpdatedBy
```

影响：

```text
建模排期中该款式可以进入待分配 / 已排期。
```

## 不应改的内容

产品组工作指引不能改：

- 项目计划上线日期
- 项目路线
- 项目等级 / 优先级
- 规划里程碑月份
- 其他组的产能
- 管理层规划调整记录

这些只能由总经理 / 产品总监通过项目规划或项目排期规划调整流程处理。

## 重新测算机制

第一版不要每次保存都自动测算。

建议流程：

```text
写入执行事实
→ 记录 ProgressUpdate
→ 标记“需要重新测算”
→ 页面提示“已有 X 项进度更新，建议重新测算”
→ 管理层或负责人点击重新测算
```

后续可复用：

- `ScheduleRun`
- `ScheduleAdjustment`
- `ProgressUpdate`

如果当前还没有正式“待重新测算”字段，可以先用页面级提示或轻量派生状态，不急着改 schema。

## 每日动作清单生成规则

产品组工作指引主要读取 5 类信号：

| 信号来源 | 读取内容 |
|---|---|
| 项目排期 | 当前关键任务、风险等级、预测完成日期、延期原因 |
| 项目任务 | 实际完成、预计完成、是否阻塞、最后更新时间 |
| 建模排期 | 未分配款式、送审 / 等反馈 / 修改、全部通过日期 |
| 用户数据 | 项目组、产品负责人、产品美术、人员归属 |
| 规划调整 | 管理层提前的里程碑、计划调整要求 |

必须进入每日动作清单：

- 当前关键任务未完成
- 任务有延期风险
- 任务必然延期
- 进行中超过 3 天未更新
- 任务缺少预计完成日期
- 管理层提前了里程碑
- 款式清单未录入
- 原画已到计划完成窗口但未过审
- 建模款式未分配
- 建模卡在送审 / 等反馈 / 修改
- 项目阻塞

## 每周动作清单生成规则

适合进入周度汇总：

- 本周应完成的任务
- 下周即将开始的任务
- 本周有延期风险的项目
- 本周有建模分配压力的项目
- 本周需要版权方反馈的项目
- 本周需要工厂 / 供应链配合的项目
- 本周新增规划调整
- 本周已完成但延期完成的任务

## 优先级展示

内部逻辑可以分为：

```text
P0：必然延期 / 阻塞 / 管理层提前要求
P1：延期风险 / 超 3 天未更新 / 建模卡住
P2：本周应完成 / 缺少预计完成日期 / 未录入款式
P3：下周准备 / 普通跟进
```

页面文案不要直接展示 P0/P1，建议翻译为：

```text
紧急
重要
本周处理
提前准备
```

## 动作卡片字段

每条动作卡建议包含：

- 项目名称
- 动作标题
- 动作原因
- 负责人
- 产品美术
- 所属项目组
- 来源模块：项目排期 / 建模排期 / 规划调整
- 计划日期
- 预测日期
- 最近更新时间
- 建议动作按钮

建议按钮：

- 标记完成
- 更新预计时间
- 标记阻塞
- 解除阻塞
- 补充进度
- 录入款式
- 管理款式
- 查看建模
- 查看项目

不同动作显示不同按钮，不要所有卡片都堆满。

## 动作关闭规则

动作不是单独关闭，而是由事实变化自动消失。

例如：

- 任务已完成 → 任务动作消失
- 预计完成日期已填写 → 缺少预计时间动作消失
- 款式清单已录入 → 录入款式动作消失
- 款式已分配 → 未分配动作消失
- 阻塞解除 → 阻塞动作消失

## 款式清单与建模排期边界

```text
产品组创建款式。
建模排期推进款式。
项目排期根据款式结果重新预测。
```

建模排期负责写：

- 建模师分配
- 外包供应商
- 建模计划开始 / 完成
- 建模实际开始 / 完成
- 建模状态
- 送审、等反馈、修改
- 修改反馈记录

产品组工作指引负责写：

- 款式创建
- 款式是否必做
- 款式名称
- 款式难度和预估工时
- 原画过审状态
- 原画过审日期

## 验收标准

每次修改本模块后至少检查：

```powershell
npm run lint
npm run build
```

浏览器检查：

- `/product-guide` 页面无报错
- 仍能看到基础版的顶部指标、筛选、列表、项目组视图、详情
- 可以对任务执行「标记完成」
- 标记完成必须写入实际完成日期
- 可以填写预计完成日期
- 可以标记 / 解除阻塞
- 可以录入款式清单并生成 `ModelingTask`
- 生成的款式能在建模排期中出现
- 产品组不能通过工作指引修改规划基线
- 保存后能提示需要重新测算
