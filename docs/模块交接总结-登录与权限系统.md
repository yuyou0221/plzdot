# 模块交接总结-登录与权限系统

最后更新：2026-05-25

## 模块范围

本轮处理「登录与权限系统」基础版，目标是让内部工具不再裸露访问，并让写操作按角色做基础限制。

本轮不处理：

- 修改本人密码页
- 忘记密码
- 审计日志
- 更细粒度的全模块按钮权限
- 正式环境强制替换默认管理员密码

## 已完成

新增登录页：

```text
/login
```

新增接口：

```text
POST /api/auth/login
POST /api/auth/logout
```

当前会话机制：

- 使用 httpOnly 签名 Cookie 保存会话。
- 未登录访问页面会跳转到 `/login`。
- 未登录访问受保护 API 返回 `401`。
- 侧边栏增加「退出登录」。

用户数据页已增加账号字段：

- 登录名
- 权限角色
- 初始 / 重置密码字段

## 默认管理员

首次打开登录页时，如果没有任何登录账号，会自动创建默认管理员。

```text
登录名：admin
密码：admin123456
```

注意：后续应尽快做「修改密码」或手动在用户数据页重置默认管理员密码。正式环境不能长期使用默认密码。

测试 / 正式部署注意：

```text
生产环境必须配置 AUTH_SECRET。
首次创建管理员时，生产环境必须配置 INITIAL_ADMIN_PASSWORD。
```

## 权限角色

当前角色：

| 角色 | 权限 |
| --- | --- |
| admin | 管理员，用户数据可写，业务数据可写 |
| manager | 管理者，业务数据可写 |
| viewer | 只读成员 |

当前写权限口径：

- 用户数据写接口仅 `admin` 可操作。
- 项目排期、建模任务、产品组工作指引等业务写接口允许 `admin / manager`。
- `viewer` 只读。

## 验证结果

已执行：

```text
npm run lint
npm run build
```

验证通过：

- `lint` 通过。
- `build` 通过。
- 浏览器访问 `http://127.0.0.1:3000/`，未登录会跳转 `/login`。

## 重要注意事项

- `next.config.ts` 增加了 `allowedDevOrigins: ["127.0.0.1"]`，用于本地浏览器验证时避免 Next dev 资源被拦截。
- 当前还有一些非本轮历史 / 并行改动在工作区中，不要误回退。
- 当前已有基础登录，但各模块的「默认自己组」「当前建模师个人页」还没完全绑定登录用户；建模排期独立管理层看板已移除。
- 当前是基础角色权限，不是完整权限系统。后续仍需要按钮级权限、审计日志和更细粒度的模块权限。

## 后续建议

优先补：

- 修改本人密码。
- 首次登录强制修改默认密码。
- 用户数据页重置密码的更明确交互。
- 后续如果重建管理层统计视图，再按 `admin / manager` 或指定角色限制可见。
- 产品组工作指引默认进入当前用户所在项目组。
- 建模个人信息页默认读取当前登录建模师。
