# 模块交接总结-建模排期基础版

最后更新：2026-05-25

## 模块范围

本轮只处理「建模排期」模块，没有处理财务、知识库、权限、送审 AI、项目排期大重构。

建模排期当前定位：

- 读取项目排期中的建模里程碑
- 读取和展示款式级 `ModelingTask`
- 支持建模师分配、外包标记、状态推进和反馈记录的基础保存
- 给管理层、建模负责人、个人建模师提供不同视角

不允许建模排期直接修改规划视图、项目计划上线日期或项目排期基线。

## 做了什么

### 1. 建模里程碑基础界面

默认显示从项目排期测算数据中提取的建模里程碑：

- 本月要完成
- 之前未完成
- 下个月要完成

建模里程碑目前按项目排期任务编号 `7-10` 聚合。

项目已经进入红蜡、模具、大货、已完结等后续阶段时，历史建模里程碑不再作为当前逾期重点显示。

### 2. 管理层看板

原来的款式状态列看板已调整为「管理层看板」。

当前用途：

- 查看总体建模任务
- 查看建模师任务负载
- 查看未分配、外包、卡住、超载情况
- 查看项目级建模进度
- 点击款式卡查看详情

注意：当前只是页面视角命名为管理层看板，权限限制还没有接入。后续应只允许总经理或指定管理角色查看。

### 3. 款式看板

新增一套和管理层看板分开的「款式看板」。

当前款式看板按人分组，而不是按状态分列：

```text
未分配
冷茂华
  款式1
  款式2
  款式3
外包中
```

款式看板里的建模师身份卡不显示产能数字。

已通过款式不会出现在排期中的款式列表里。

「已通过款式」入口放在款式看板内部，不放在最左侧菜单。已通过页签的展示格式和款式看板一致，也是按人 / 未分配 / 外包分组。

### 4. 个人信息页

在 `/modeling` 内新增「个人信息」视图。

当前可以查看：

- 当前建模师自己的建模款式
- 个人任务数量
- 进行中任务
- 已通过款式
- 逾期 / 长时间未更新提醒
- 个人已通过款式清单

因为还没有接入登录权限，当前用建模师下拉选择来模拟「当前用户」。后续接入真实登录后，应自动读取当前登录建模师。

### 5. 真实 ModelingTask 优先

当前数据读取规则：

- 如果数据库存在真实 `ModelingTask`，优先显示真实款式
- 只有没有真实款式时，才根据 `Project.styleCount` 生成虚拟款式
- 虚拟款式会明确标注「虚拟 / 待补充款式名」
- 虚拟款式不能保存到数据库

### 6. 拖拽和保存

当前支持：

- 真实款式拖拽到建模师后保存 `modelerId`
- 保存款式状态
- 保存外包状态
- 保存送审 / 等反馈 / 修改 / 已通过等状态
- 已通过时写入实际完成时间
- 记录建模反馈

虚拟款式拖拽仍然只是前端草稿，不持久化。

## 新增 / 修改 API

### `PATCH /api/modeling/tasks/[id]`

用于保存单个建模款式的基础信息。

当前支持：

- 分配建模师
- 修改状态
- 标记外包
- 设置实际开始 / 完成
- 已通过时写入实际完成日期
- 写入反馈记录

### `POST /api/product-guide/modeling-tasks`

产品组工作指引用于创建款式级建模任务的接口。

当前口径：

- 产品组工作指引负责创建真实款式事实
- 建模排期负责分配和推进款式建模
- 项目排期只读取建模结果，不直接管理每个款式

## 当前业务规则

超载规则：

```text
建模师排队款式数 > 4
```

未更新提醒：

```text
建模中 且 超过 3 天未更新
```

建模状态：

- 未分配
- 已排期
- 建模中
- 已送审
- 等反馈
- 已通过
- 外包中
- 暂停
- 取消

推荐状态流转：

```text
未分配 -> 已排期 -> 建模中 -> 已送审 -> 等反馈 -> 建模中 / 已通过
```

特殊状态：

```text
外包中 / 暂停 / 取消
```

项目级建模进度只按真实款式计算。已经全部通过的项目不会继续出现在项目建模进度面板里。

## 对项目排期的影响

当前建模排期不会直接修改项目规划视图，也不会直接修改项目计划上线日期。

已经具备的数据输出：

- 项目建模总款式数
- 已通过款式数
- 进行中款式数
- 未分配款式数
- 外包款式数
- 是否全部通过

后续建议：

- 所有必做款式已通过后，生成「可回写项目任务」提示
- 用户确认后再回写项目任务「根据效果图建模」
- 回写后触发预测视图 / 压力预测重新测算

## 对产品组工作指引的影响

产品组工作指引仍然是款式事实的源头。

建模排期会向产品组工作指引反向暴露：

- 哪些款式未分配
- 哪些款式原画未过审
- 哪些款式卡在送审 / 等反馈 / 修改
- 哪些项目建模可能影响排期
- 哪些款式需要产品美术验收

当前 Excel 和手动录入属于过渡数据补齐方式。长期应由产品组工作指引创建和维护款式清单。

## 对用户数据的影响

当前使用的用户字段包括：
