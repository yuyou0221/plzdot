# 模块交接总结-建模排期基础版

最后更新：2026-05-31

## 模块范围

本模块只处理「建模排期」。不处理财务、知识库、权限登录、送审 AI、项目排期大重构、产品组工作指引大改。

当前定位：

- 建模排期负责款式级 `ModelingTask`。
- 产品组工作指引提交款式基础资料、任务 7/10 启动事件、审核 / 送审结果。
- 建模排期负责建模师分配、外包状态、建模计时、成果提交、反馈记录和项目级建模进度。
- 项目排期主动读取建模排期提供的完成事实。
- 建模排期不主动回写项目排期，不写 `ProjectTask`，不修改项目规划基线和计划上线日期。

## 已实现功能

### 1. 建模里程碑

- 默认进入 `里程碑` 视图。
- 显示本月要完成、之前未完成、下个月要完成的建模里程碑。
- 里程碑读取项目排期任务 `7-10`。
- 已经进入后续阶段或已完结的项目，不再作为当前建模逾期重点展示。

### 2. 款式看板

- 真实 `ModelingTask` 优先显示。
- 没有真实款式时，才基于 `Project.styleCount` 生成虚拟款式。
- 虚拟款式明确标注“虚拟 / 待补充款式名”，不能保存到数据库。
- 款式看板按建模师 / 未分配 / 外包分组展示。
- 已通过款式不显示在活跃排期列表。
- 已通过款式在款式看板内部以同样格式查看。
- 款式详情可全屏打开。
- 款式详情显示累计工时、反馈次数、最新提交成果、检修 / 送审记录。

### 3. 款式清单提交与建模确认

- 支持系列级款式清单提交。
- 款式清单提交后进入 `待确认`。
- 提交后生成建模专属待办：`款式清单待确认`。
- 待办打开同一张系列款式清单页。
- 建模侧可整批确认，确认后全部进入 `未启动`。
- 建模侧可整批退回补充，退回必须填写原因并写入反馈记录。
- 退回后可重新提交完整系列。
- 重新提交缺少原系列款式时接口会拒绝，避免靠缺失静默删除款式。
- 每次提交记录 `styleSubmissionBatchId` 和 `styleSubmissionVersion`。
- 确认后返回给产品组程序保存映射用的款式级任务清单，包括 `modelingTaskId`、`sourceStyleId`、`projectTaskId`、`taskNo`、款式序号、款式名称、是否第一款、是否必做和当前状态。

### 4. 任务 7 / 10 启动事件

- 任务 7 只启动第一款：`未启动 -> 未分配`。
- 任务 10 只启动其余款式：`未启动 -> 未分配`。
- 任务 8 / 9 会被拒绝，不产生款式级建模任务。
- `待确认`、`退回补充` 款式不能启动。
- 重复启动保持幂等，并返回启动 / 跳过摘要。
- 启动事件只改变状态，不分配建模师，不开始建模计时，不修改项目排期。

### 5. 建模师输入

- 支持单款分配建模师。
- 支持单款标记外包。
- 支持外包状态保存。
- 建模状态只读展示，不支持手动状态推进。
- 支持开始建模计时。
- 同一建模师开始另一款时，系统自动停止上一款计时。
- 建模师提交成果时，系统自动停止本款计时。
- 建模工时按分钟累计，写入 `ModelingWorkLog`。
- 建模师分配 / 外包切换写入 `ModelingAssignmentHistory`。
- 计时显示按 5 分钟刷新，开始、自动停止、提交后立即刷新。
- 款式看板已移除全选和多选，只保留单款详情与单款操作。

### 6. 建模成果提交与审核 / 送审

- 建模师提交成果后，款式进入 `待验收`。
- 提交成果会生成 `modeling_work_submitted` 主动事件给产品组。
- 产品审核 / 送审结果已通过建模页内模拟器验证。
- 内部通过可送审：`待验收 -> 待送审`。
- 内部不通过：`待验收 -> 排队中`，必须填写文字反馈。
- 已送审：`待送审 -> 已送审`。
- 等反馈：`待送审 / 已送审 -> 等反馈`。
- 送审通过：`待送审 / 已送审 / 等反馈 -> 已通过`。
- 送审不通过：`待送审 / 已送审 / 等反馈 -> 排队中`，必须填写文字反馈。
- 通过类和过程类可以不填文字反馈，但允许图片 / PDF / PPT 反馈链接。
- 审核必须锁定最新一次建模成果提交，旧提交记录不能被审核。

### 7. 项目排期可读事实

- `GET /api/modeling/projects/[projectId]/progress` 已稳定为项目排期可读事实接口。
- 固定统计任务 7 + 任务 10 的所有必做款式。
- 全部必做款式已通过时返回：
  - `allRequiredStylesApproved = true`
  - `canProjectScheduleTreatModelingDone = true`
  - `lastRequiredStyleApprovedDate`
- 任意必做款式未通过时返回未通过必做款式和阻塞款式。
- 非必做款式未通过不影响建模完成事实。
- `/modeling` 项目建模进度面板显示“项目排期读取状态”。
- `/modeling/contract-test` 提供“项目排期读取模拟”。
- 页面不提供“确认回写”“写入项目排期”“完成项目任务”等按钮或文案。

## 主动输出事件

当前建模排期只主动输出给产品组工作指引：

```text
style_list_confirmed
style_list_returned
modeling_work_submitted
```

说明：

- `modeling_project_all_approved` 不作为主动输出事件。
- 项目必做款式全部通过属于对外可读完成事实，由项目排期主动读取。
- 产品组如果没有接住接口返回，可以通过 `GET /api/modeling/product-guide-events` 补读事件。

## 当前 API

```text
POST /api/modeling/style-submissions
POST /api/modeling/style-confirmations
POST /api/modeling/style-start-events
POST /api/modeling/review-results
POST /api/modeling/style-cancellations
POST /api/modeling/style-reopen-events
GET  /api/modeling/product-guide-events
GET  /api/modeling/projects/:projectId/styles
GET  /api/modeling/projects/:projectId/progress
PATCH /api/modeling/tasks/:id
POST /api/modeling/tasks/:id/work-submissions
POST /api/modeling/tasks/:id/work-timer
POST /api/modeling/contract-test/projects
POST /api/modeling/contract-test/cleanup
```

`PATCH /api/modeling/tasks/:id` 是过渡期通用单款基础编辑入口，后续应拆成更明确的事件接口。

`POST /api/product-guide/modeling-tasks` 作为兼容旧入口保留，内部桥接到建模排期款式清单提交契约，提交后进入 `待确认`，不是直接进入 `未分配`。

## 对项目排期的影响

- 建模排期不主动修改项目排期。
- 建模排期不写 `ProjectTask`。
- 建模排期不触发重新测算。
- 项目排期后续主动读取 `GET /api/modeling/projects/:projectId/progress`。
- 项目排期自行决定是否把任务 7 / 10 建模事实视为完成、是否写执行事实、是否重新测算。

## 对产品组工作指引的影响

- 产品组工作指引仍然是款式基础资料和审核 / 送审结果的来源。
- 产品组不维护建模师、外包供应商、建模状态和产能。
- 产品组需要保存建模确认后返回的 `modelingTaskId` 映射。
- 产品组需要读取 `style_list_returned` 处理退回补充。
- 产品组需要读取 `modeling_work_submitted` 生成内部审核待办。
- 产品组后续应调用 `POST /api/modeling/review-results` 提交审核 / 送审结果。

## 对用户数据的影响

- 建模师来源读取 `User`。
- 外包供应商来源读取 `OutsourceVendor`。
- 用户数据模块仍需补齐建模师真实产能、擅长类型、是否可排期、稳定外包供应商和外包可用产能。
