## 本轮目标

取消 `calculatedStartDate` / `calculatedFinishDate` 的保守传播口径，让真实完成、真实开始、预计完成、剩余天数和前置任务 calculated 结果可以自然拉早下游。

本轮只改 calculated 传播方式，不改：

- `planned` 口径。
- `latest` 口径。
- `currentLatest` 口径。
- #17 手板路线工期。
- #21 / #30 / #31 工期和依赖。
- #8 / #9 display-only 旁路任务。
- 项目主数据导入。
- 任务事实导入。
- 财务、用户数据、建模写入、产品组事实接口。

## 业务口径

- `plannedStartDate` / `plannedFinishDate` 仍是从 `projectStartDate` 正推出来的管理计划。
- `latestStartDate` / `latestFinishDate` 仍是从 `effectiveLaunchDate` 倒推出来的原始最晚安全线。
- `currentLatestStartDate` / `currentLatestFinishDate` 仍是从 `projectedLaunchDate` 倒推出来的动态安全线。
- `calculatedStartDate` / `calculatedFinishDate` 是当前可达预测，可以早于、等于或晚于 planned。
- `actualStartDate` / `actualFinishDate` 是真实事实，事实优先于模型推导。
- 未开始任务不能自动在过去开始；如果前置 calculated 已经早于 today，但没有实际开始事实，则从 today 开始预测。
- `finishAfter` 仍是硬完成约束，未完成任务不能早于 finishAfter 约束完成。
- `projectedLaunchDate = max(effectiveLaunchDate, earliestReadyDate)`。
- `earliestReadyDate = max(#30 calculatedFinishDate, #31 calculatedFinishDate)`，用于诊断项目最早准备好时间。

## 根因

旧逻辑会把任务 calculated 起点固定在 plannedStartDate 或 planned 传播结果上。即使前置任务提前完成、进行中任务填写了更短的 remainingDays，或者填写了早于标准工期的 expectedFinishDate，后续任务也可能仍按 baseline 慢慢走，无法反映业务实际追赶能力。

典型旧逻辑问题：

- `actualFinishDate` 只覆盖本任务，但 downstream 仍可能被 planned 下限卡住。
- `actualStartDate` 使用 `max(plannedStartDate, actualStartDate)`，无法记录早于 planned 的真实开始。
- `remainingDays` / `expectedFinishDate` 用 `max(标准工期完成日, 业务预测完成日)`，导致业务填了 10 天剩余工期，系统仍按完整标准工期预测。
- 未开始后续任务不能被前置 calculated 拉早。

## 修复内容

- 已完成任务：`calculatedFinishDate = actualFinishDate`，下游基于该实际完成日继续计算。
- 已完成任务如果早于模型约束，不推迟事实，只输出 `calculationWarnings`。
- 进行中任务：`calculatedStartDate = actualStartDate`，不再被 plannedStartDate 压住。
- 进行中任务的 `remainingDays` 优先按 `today + remainingDays`，可以早于标准工期。
- 进行中任务的未来 `expectedFinishDate` 优先作为本任务预测完成日，可以早于标准工期。
- 过期 `expectedFinishDate` 不再作为最终预测完成日，避免未完成任务停在过去。
- 未开始任务有 startAfter 前置时，优先从前置 calculated 完成日加 lag 开始；如果开始日早于 today 且没有 actualStartDate，则从 today 预测。
- 未开始任务无 startAfter 前置时，仍从 plannedStartDate 开始；如果 planned 已经过期，则从 today 预测。
- `finishAfter` 仍参与 `max(ownFinish, finishAfterConstraint)`。
- 新增项目级 `earliestReadyDate`。
- 新增任务级 `calculationWarnings`。
- 新增回归场景：`actual-pull-forward-v5`。

## 已知风险

- 本轮改变 calculated 语义，部分历史模拟场景中 calculated 日期会自然前移；这属于预期变化。
- 真实 Excel 中如果 expectedFinishDate 已过期但没有 remainingDays，系统会退回到 actualStartDate + 标准工期或 today + 标准工期，而不会假设已经完成。
- 本轮不会让粉红兔子直接回到 2026-11-20；后续仍需业务确认 #21 / #30 / #25-#27 等规则是否继续调整。
